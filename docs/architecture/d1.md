# D1 engine architecture

Scope: `src/d1/` (the Dante98 engine), specification chapters 10 (data formats), 11 (title, field, events,
menus, saves), 12 (battle) and 19 (built-in messages). The engine is one class, `d1::Game`, whose methods are
split over several source files. The battle uses a separate helper class, `d1::Battle`, that works on the `Game`.

Strings built into RPG.EXE (chapter 19) are written as UTF-8 literals and converted with `S("…")`
(`core::utf8ToSjis`). Data names are shown as the raw 17-byte field up to NUL, with padding (`nameOf`).

## Main state

- `db` (`Data`): read-only records. Images are decoded at load time into `core::Image` (palette indices).
  `db.mapCell(screen, x, y)` reads a pattern number; `db.land(p)` / `db.blocked(p)` read MAPPATN bits.
- Saved game state (10 §10): `heroes[8]` (`Hero`: level, status, HP, MP, exp, equipment, plus the
  *recorded* max HP/MP of 11 §10.1), `curScreen`, `heroX/heroY`, `gold`, `fieldBgm`, `party[4]`,
  `switches[25]` (200 bits), `invId/invCnt[50]`, ship/airship/warp screens and positions, `vehicle`,
  `palMode`, warp palette and BGM. Values not saved (vehicle graphics and BGMs, battle BGM, ring) come from
  `db.start`.
- Field runtime: `blockBuf_` (copy of the current block's IVENT file; positions are written back into it,
  11 §5.7), `cells_[240]` (current screen, temporarily rewritten), `objs_[241]` (`Obj`; slot 0 is the hero,
  `x == kErased` means erased, `event` is the event offset or −1/−2 for ship/airship), `objCount_`,
  `heroChr_`, `encCounter_`, `invCursor_`, `lastTouched_`, `lastJudge_`.
- Event runtime: `evObj_`, `evChrLoaded_/evChr_` (CHR loaded by 0x76), `msgOpen_`.
- Message area (11 §7.1): `mX0_, mY0_, mW_, mH_` and cursor `mC_/mR_`, shared by events, menus and battle.
- `scr_` (`core::Screen`): the D1 engine draws only on the graphic plane and uses `frameBorder` for the
  black text-layer border (01 §1.7), `scrollLine` for the battle slide-in and `hOffset` for shakes.

## Screen flow

`run()` (11 §2.1): seed RNG with 1 once, then loop: `titleScreen()` (skipped with `--no-title`) →
`titleMenu()` until new game or a successful load → `gameStart()` → `applyDebugStart()` (first time only) →
`fieldLoop()` → fade out 1→16, BGM stop, border off → back to the title. The engine never quits by itself.

`fieldLoop()` (11 §6.1) repeats: one frame if none passed since the last restart, `setup(first)`, draw all
objects, run the first auto-start event, then `frameProc()` until it asks for a restart. `frameProc()`
(11 §6.2) handles in order: standing on an object, examine (ok), main menu (cancel, on foot), hero movement
(doors, bumping, screen switch with scroll), NPC update, hero drawing, encounter check and walking poison on
a completed step, and pads to 3 frames. Restarts return `FP::Restart` or `FP::RestartFirst`; `ended_` marks
game over, ending or "quit" and makes the loop exit. Main menu results are `MM::Normal/Reload/Quit`.

## Event interpreter

`runEvent(o)` (11 §8.1) copies `blockBuf_`, selects the page (`selectPage`, pages 3→1 with at least one
condition, else 0) and executes from page start + 10 until FF FF at a command boundary. Each command is a
`case` in one `switch`, advancing by its length (10 §9.5); undefined opcodes advance 1 byte when executed,
3 when skipped. Yes/no (0x3F/0x3A) skips with `cmdLen`. Commands that end the game (0x68/0x70 wipe-out,
0x71 ending, 0x79 lost battle) set `ended_` and return `false` without the normal epilogue. Shops (0x73,
11 §8.3) and the inn (0x6E) are implemented next to the interpreter. With `-v`, every executed opcode is
logged as `[d1 op XX]`.

## Battle

`Game::battle(group, eventBattle)` creates a `Battle` and returns 1 (victory), 0 (wiped out) or −1
(escaped). `Battle::run` (12 §3): reseed the RNG with the low 16 bits of the frame counter, PALET2,
thinning roll, enemy slots and columns, party battle stats, slide-in, then rounds: `commandInput()` (§6) →
`computeOrder()` (§7, swap sort + 4 pair swaps) → `turn()` per combatant (§8; party via `decideParty`, enemies
via `decideEnemy`) → `roundEnd()` (§16). Actions go through `doAction` (§12), `castMagic`/`effect`/
`showResult`/`groupProc` (§13) and `useItem` (§14). Combatants are numbered 0–3 (party slots) and 4–8
(enemies); `alive()`, `hp()`, `status()` and `name()` hide the difference, and an empty party slot reads as
HP 0, status 0, empty name with writes discarded (12 §1.2). `cleanup()` implements 12 §17.4.

## Timing, input and RNG

- `frame()` presents one VSYNC through `Host::vsync`, increments `frameCounter_` and `totalFrames_`, and
  flips the animation phase on multiples of 16. Menus reset the counter with `resetAnim()` (11 §1.2); this
  affects NPC timing and the battle seed.
- `waitMs(ms)` converts with `core::MsBalance` at 56.4 Hz, carrying the fraction for the engine's lifetime
  (01 §3.3). `fade(a,b)` is 2 frames per step.
- Input is polled through `in()`. `dirKey()` applies up > right > down > left. `waitRelease()` waits until
  ok/cancel/directions are released. `waitPress()` is the "key-press wait" of 11 §1.3: it checks the fast
  key once at the start (one frame and done), then waits for ok/cancel/direction. `waitAnyKey()` never looks
  at the fast key (used after 「魔法は使えません」); the title and ending waits accept only ok/cancel.
- RNG: `core::Rng` (Turbo C LCG), seeded with 1 at program start and reseeded at each battle start. Draw
  order follows 11 §14 and 12 §20; `variance()` draws twice only for values above 3.

## Sound requests

`se(n)` sends the D1 effect number unchanged. `bgmChange(n)` fades 0→15 in 20 ms steps, stops and requests
BGM number n (`BGM\BGMnn.MML`); `bgmStop()` fades and stops (11 §1.4). Fixed numbers are listed in 11 §1.4
and 12 §18.6.

## Save format

`buildSave()` / `applySave()` implement the 270-byte layout of 10 §10 (signed 16-bit HP/MP, signed 32-bit
exp; files of 266–269 bytes are zero-padded). `saveSlot(k)` writes `SAVEDATA.{k+1}` in the game folder;
`loadSlot(k)` fails silently on a missing or short file. A load followed by a save is byte-identical.

## Debug start options

`applyDebugStart()` runs once, right after the first game start (new game or load), in the order of
01 §9.2: `--gold`, `--item`, `--warp M,X,Y` (map AND 1023, block reload and redraw), `--battle G` (random
encounter effect, battle, game-over check).

## Tests

`tests/test_d1.cpp` (23 tests) uses `ScriptHost` (scripted per-frame input with a probe) and the `D1Test`
friend for private access. It covers: exp table, signed arguments, loading all 20 games and walking all
event files (73940 events, every page ends at FF FF), agasa start info, the earth save round trip, block
offsets, page conditions, message wrapping, the encounter counter, walking poison, palette modes, doors and
keys, event erase, enemy AI retry limit, victory rewards, wipe-out vs. game over, the fast-key rules of the
key waits, 0x76/0x77 with bad arguments and empty-slot battle targets. `tools/run_all_refs.sh` compares all
sample games against `reference_shots/`; every D1 game with references matches on all 5 shots.
