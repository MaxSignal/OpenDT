## 1. 時間と入力の基礎

### 1.1 VSYNC とカウンタ
- 時間の基本単位は VSYNC（垂直同期）。実時間で表示を進める速さは 56.4 Hz（→ 01 章）。56.42 Hz という値は、D2 のミリ秒の待ちをフレーム数に換算するときだけ使う（下記）。1 VSYNC ごとに次をこの順に行う：
  1. 2 つの VSYNC カウンタを 1 増やす：**自走カウンタ**（アニメーション位相とフィールドの 3 VSYNC 周期に使う）と **待ちカウンタ**（各種待ちループが 0 に戻して使う）。
  2. 飛空艇搭乗中なら影の点滅を更新（§9.3）。
  3. 画面を 1 フレーム出力。
  4. キー状態を取り込み、キーバッファを更新（§1.3）。
- 自走カウンタはイベントの一部の命令（ブラックアウト／イン、ホワイトアウト／イン → 22）と戦闘の一部の演出（→ 24）で 0 に戻される。そのためフィールドの 3 VSYNC 周期の位相やアニメーションの位相もそこでずれる。
- 「ミリ秒の待ち」は 参照実装では VSYNC 数に換算する（ms × 56.42 ÷ 1000 を端数繰り越しで累積し、1 以上になるたび 1 VSYNC 待つ）。原本は別のタイマで実時間待ちしている【未確認】。

### 1.2 待ち時間の単位
- **待ち単位 n**：待ちカウンタを 0 にし、カウンタが n×7 になるまで VSYNC を待つ。開始時点で SHIFT が押されていれば n×3。戦闘・メニューのメッセージ間の待ちに使う（→ 23・24）。
- 文字表示の待ち（全角 16ms、半角 8ms。SHIFT 中は待たない）、イベントの「ウェイト」（n×100ms）などは 22。

### 1.3 キー入力
**キーバッファ**（決定・取消・カーソルの「押された」事象を溜める。最大 16 個、溢れた分は捨てる）：
- 対象キー：ESC（取消）、RETURN（決定）、SPACE（決定。RETURN と同じ扱い）、カーソル ↑↓←→、テンキー 8・2・4・6（カーソルと同じ扱い）、ROLL UP/ROLL DOWN（変数エディタのみ → 23）。
- キーが押された瞬間に 1 個積む。
- キーリピート（参照実装での BIOS リピートの模擬）：最後に押されたキーを押し続けていると、押下から 28 VSYNC 目に 1 個、以後 3 VSYNC ごとに 1 個積む。そのキーを離すか全キーを離すとリピート終了。
- 「キーを 1 個取り出す」は空なら「なし」を返す。「キーバッファを空にする」も多用される。

**方向キーの読み取り**（移動・キー待ちに使う。押されている状態を直接読む）：
- 「ラッチ」＝ 直前に記録した各キー（下・左・右・上・決定/取消）の押下状態。
- 「ラッチ記録」：現在の押下状態をラッチに写す。
- 「方向読み取り」：各キーについて「ラッチまたは現在押されている」を押下とみなし、
  1. 縦成分 v＝（下なら +1）−（上なら 1）、横成分 h＝（右 +1）−（左 1）。
  2. h と v が両方 0 でない（斜め）とき：直前の「単独方向」が縦だったなら横の方向（6 または 4）を、横だったなら縦の方向（2 または 8）を返す（＝後から加えた方向が勝つ）。
  3. h だけ 0 でないとき：記憶「直前は横」として 6/4 を返す。
  4. v だけ 0 でないとき：記憶「直前は縦」として 2/8 を返す。
  5. どれでもないが何かのキー（上下同時押し等、決定・取消を含む）が押されていれば 5、何も押されていなければ 0。
  （「直前の単独方向」の記憶の初期値は横。）

**SHIFT キー**：押している間、待ち単位の短縮（7→3）、文字表示の無待ち、戦闘メッセージのキー待ち省略（→ 24）、テストプレイ時の逃走必中（→ 24）。

**キー待ち（何かキーを押すまで）**：次を繰り返す：ラッチ記録 → キーバッファを空にする → 2ms 待つ → 方向読み取り → STOP 判定（§1.4）→ 読み取り結果が 0 なら「全部離された」を記録、0 以外でかつ既に「全部離された」が記録済みなら終了 → **乱数を 1 回引いて捨てる**。つまり「一度すべて離してから何か押す」まで待ち、待っている間ずっと乱数を消費する（§13）。

### 1.4 STOP キーによるイベント中断（テストプレイのみ）
- テストプレイ中、イベント実行中に STOP キー（＋CTRL）が押されていると、実行中のイベントを即座に打ち切る。参照実装では「CTRL＋取消キー」で代用。
- 判定箇所：スクリプトの各命令の実行前、選択カーソルの待ち、キー待ち、イベントの時間経過待ち（→ 22・23）。
- 打ち切り時：イベント実行中フラグを 0 にし、主人公の移動途中なら完了させ、フィールドを再描画し、通常のイベント終了処理（§7.4）を行う。イベントの戻り値は 0。
  - このときの「移動途中の完了」はイベント実行中フラグが 0 の状態で主人公処理（§6.2）を回すので、1 歩が完了すると **到着処理（歩数加算・毒・エンカウント判定）が行われる**（「重なる」イベントは STOP 押下中のため起動しない）。通常のイベント終了（§7.4 手順 5）ではフラグがまだ 1 なので到着処理は行われない。
- 同じ押下状態では新しいイベントも起動しない（§7.3）。

## 2. パレット系

### 2.1 現在パレットとトーン値
- **現在パレット**：16 色 × (R,G,B) の 8 ビット値で保持する。4 ビット値 c で設定するときは c×17 を入れる。
- **ベースパレット**：いまのチップセット（MCPnnn.ECD）のパレット（4 ビット値）。色調変更の基準。
- **トーン値** T（整数、通常 100）。画面に出す色は、各成分について v ＝ 現在パレット値 ÷ 16（0〜15）として：
  - T ≤ 100：v × T ÷ 100（T が負なら 0 として計算）
  - 100 < T < 200：15 − (15 − v) × (200 − T) ÷ 100
  - T ≥ 200：15
  （÷ は切り捨て。結果 0〜15 をハードウェアの 4 ビットパレットとして出す → 01）
- 「表示更新」＝ 上式で 16 色を計算して表示パレットに反映すること。現在パレットやトーン値を変えただけでは表示は変わらず、表示更新で初めて反映される。

### 2.2 ブラックアウト／ブラックイン／ホワイトアウト／ホワイトイン（速度 s）
いずれも最初に T を初期値にして 1 VSYNC 待ち、その後「表示更新 → s VSYNC 待つ → T を 6 変える」を条件が満たされる間繰り返し、最後に T を終値にして表示更新する。

| 種類 | 初期値 | 1 回の変化 | 繰り返し条件（変化後に判定） | 終値 | 表示される T の列 |
|---|---|---|---|---|---|
| ブラックアウト | 100 | −6 | T > 0 | 0 | 100, 94, …, 4, 0 |
| ブラックイン | 0 | +6 | T < 100 | 100 | 0, 6, …, 96, 100 |
| ホワイトアウト | 100 | +6 | T < 200 | 200 | 100, 106, …, 196, 200 |
| ホワイトイン | 200 | −6 | T > 100 | 100 | 200, 194, …, 104, 100 |

所要 VSYNC ＝ 1 ＋ 17 × s（最後の表示更新の後は待たない）。システムが使う速度：タイトル・ニューゲーム・ロード・フィールド開始・終了 は 1、宿屋・全滅・ワープ/脱出は 2。

### 2.3 即時の暗転・白転
「T を 0（または 200）にして表示更新」だけを行う箇所が多数ある（画面の描き換えを隠すため。描き終えたら「1 VSYNC 待って T=100 にして表示更新」）。

### 2.4 色調変更（種別 k、速度 s）
1. 開始色 ＝ 現在パレットの各値 ÷ 17（4 ビット値に戻す）。
2. 目標色 ＝ ベースパレットに種別 k の加工を施したもの（下表）。
3. 状態ブロックの色調値 ← k＋1（8 ビットに切り詰め。k＝−1 や 65535 なら 0＝通常）。
4. 1 VSYNC 待ち、待ちカウンタを 0 にする。この待ちは速度 s に関係なく**常に**行う（s＝0 でも、設定だけの s＝−1 でも 1 VSYNC 進む。マップ読込・ロード・戦闘後・ピクチャ後の再適用でも 1 フレーム進む）。（v1.1 で追記）
5. s > 0 のとき：j＝0〜6 について、現在パレット ← 開始色 ＋ (目標色−開始色)×j÷8（差は符号付き、÷ は 0 方向切り捨て）を設定し、待ちカウンタが j×s 以上になるまで待って表示更新。その後、待ちカウンタが 7×s 以上になるまで待つ。
6. 現在パレット ← 目標色。s ≥ 0 なら表示更新（s＝−1 は設定だけで表示しない。マップ読込やロード後の「色調の即時再適用」はこの形）。

**加工**：各色について (R,G,B) ← ベースの値、R₀,G₀,B₀ はその色のベースの元の値（加工前）。「灰」＝ min(15, (R+G+B)÷3 + 3) を **その時点の**（直前の操作で書き換えた後の）R,G,B で計算する。各操作（加算・代入）の直後に 0〜15 に丸める（したがって「+2 してから −1」は「+1」と同じではない）。

| 種別 | 操作（左から順に） | 想定される用途 |
|---|---|---|
| 0 | R+=4, G+=4, B+=4 | 明るく |
| 1 | R−=4, G−=4, B−=4 | 暗く |
| 2 | R=灰, G−=8, B−=7 | 赤 |
| 3 | R=灰, G=灰, B−=7 | 黄 |
| 4 | R−=8, G=灰, B−=7 | 緑 |
| 5 | R−=8, G=灰, B=灰, B+=2 | 水色 |
| 6 | R−=7, G−=7, B=灰, B+=2 | 青 |
| 7 | R=灰, G−=8, B=灰, B+=2 | 紫 |
| 8 | g=灰 を 1 回計算し R=G=B=g | 白黒 |
| 9 | g=灰; R=G=B=g; R+=2; G+=2; G−=1; B−=2; 最後に R=(R×7+R₀)÷8, G=(G×7+G₀)÷8, B=(B×7+B₀)÷8（この混合は丸め不要） | セピア |
| 10 | g=灰; R=G=B=g; R+=4; G+=2; G−=3; B+=2; B−=2; 最後に種別 9 と同じ 7:1 混合 | 夕焼け風 |
| 11 | R−=4, G−=4, B−=2 | 夜 |
| その他（−1、65535 等） | 加工なし（ベースそのまま） | 通常に戻す |

（用途名は本仕様の推測。数値が正。）

### 2.5 フラッシュ（イベント命令）
1. i＝0〜7：1 VSYNC 待ち、T＝120＋6i で表示更新（120〜162）。
2. i＝3,2,1,0：1 VSYNC 待ち、T＝120＋12i で表示更新（156,144,132,120）。
3. 1 VSYNC 待ち、T＝100 で表示更新。
計 13 VSYNC。

### 2.6 画面揺れ（イベント命令）
3 回繰り返す：2 VSYNC 待ち → グラフィック画面の表示開始位置を 1 ワード（16 ドット）進める（画面全体が 16 ドット左にずれ、右端には次のラインの先頭が見える → 01）→ 2 VSYNC 待ち → 元に戻す。計 12 VSYNC。テキスト層は動かない。

## 3. 起動・タイトル・ゲーム開始と終了

### 3.1 起動
1. 20 の必須ファイルを読み込む（GAIJI → MAPNAME → ITEM → MAGIC → WORD → ENEMY → PLAYER の順。順序は結果に影響しない）。RPG.EXE からビルドを判別（20 §10）。TITLE.DAT を読む。
2. 乱数の種を設定（§13）。
3. 動作モードを決める：**通常モード**（タイトル画像を表示）か **テストプレイモード**（エディタからのテスト実行。タイトル画像を表示せず、デバッグ機能が有効）。参照実装ではコマンドラインオプション `--no-title` でテストプレイモード。原本でどう区別するか（起動引数の有無など）は【未確認】（サンプルの BAT はすべて引数なしで `RPG` を起動している）。クリーン実装は設定項目として持ち、既定は通常モードとする。

テストプレイモードで変わる点（すべて）：
- タイトル画像の表示（フェード・キー待ち）を省略（§3.3）。
- フィールドメニュー画面にマップ情報ウィンドウ（`MAP=nnn:マップ名(X=xxx,Y=yyy)`）を表示（→ 23）。
- システムメニューに「デバッグ」（スイッチ表示・変数編集・敵出現オン/オフ）が加わる（→ 23）。
- STOP（＋CTRL）でイベントを中断できる（§1.4）。
- 戦闘で SHIFT を押しながら逃げると必ず成功（→ 24）。

### 3.2 タイトルループ（ゲーム全体の外側のループ）
以下を繰り返す。
1. BGM を停止。
2. パーティ記録 12 件を PLAYER.DAT の値に、状態ブロックを PLAYER.DAT の初期値に戻す（20 §2.2 の上書き 2 箇所を含む）。所持品・スイッチ・変数はここでは戻さない（ニューゲーム時に初期化）。
3. タイトル画像（§3.3）。
4. タイトルメニュー（§3.4）。「ゲーム終了」が選ばれたらプログラム終了。
5. フィールドのメインループ（§11）へ。
6. メインループからは「タイトルへ戻る」か「終了」で抜ける：
   - タイトルへ戻る：戦闘での全滅（ゲームオーバー）、イベント中の全滅、イベント命令「タイトルへ戻る」（→ 22）。手順 1 から繰り返す。
   - 終了：システムメニューの「終了」（ブラックアウト速度 1 の後）、イベント命令「ゲーム終了」。BGM を停止してプログラム終了。

### 3.3 タイトル画像
1. 1 VSYNC 待ち、T＝0 で表示更新。テキスト層を全面透明にする。グラフィック画面を色 0 で消去。表示開始位置のずれを 0 に。
2. TITLE.DAT がある場合（20 §8.4）：
   1. 現在パレット ← TITLE.DAT のパレット（8 ビット値のまま）。
   2. 画像を 640×400 で全面に描く。
   3. テストプレイモードでなければ：ブラックイン（速度 1）→ キー待ち（§1.3。乱数を消費する）→ ブラックアウト（速度 1）。このキー待ちの STOP 判定（§1.4）は常に無効（イベント実行中でなく、そもそもテストプレイモードではこの待ち自体を行わない）。（v1.1 で追記）テストプレイモードでは何も表示しないまま次へ（パレットは TITLE.DAT のものが残る）。
3. TITLE.DAT が無い場合：現在パレットの色 0 ← (0, 0x55, 0x55)、色 14 ← (0,0,0)、色 15 ← (0xFF,0xFF,0xFF)。他の色は変えない（直前のプレイのパレットが残る）。

### 3.4 タイトルメニュー
以下を繰り返す。
1. T＝0 で表示更新。グラフィック画面を色 14 で消去。
2. ウィンドウ（左上 (232,144)、幅 168、高さ 96。ウィンドウの描き方は 23）。項目を色 15 で (264,160)「ニューゲーム」、(264,184)「コンティニュー」、(264,208)「ゲーム終了」。
3. 1 VSYNC 待ち、T＝100 で表示更新。
   （色はその時点の現在パレットの色 0／14／15。TITLE.DAT があればそのパレットの色、無ければ §3.3 の 3 色。）
4. 選択カーソル（ウィンドウ位置 (232,144)、3 項目、初期 0、**取消不可**。カーソル処理は 23）。
5. 「ニューゲーム」：ブラックアウト（速度 1）→ 全員の派生値を再計算（20 §2.3）→ ニューゲーム初期化（§3.5）→ マップ進入（§4.2）→ 現在の BGM を再生 → メインループへ。
6. 「コンティニュー」：スロット選択ウィンドウ（左上 (264,208)、幅 120、高さ 120、「データ１」〜「データ４」）で選択（取消可）。取消なら手順 1 へ。選んだスロットのロード（20 §9.3）に成功すればメインループへ、ファイルが無ければ手順 1 へ。
7. 「ゲーム終了」：ブラックアウト（速度 1）→ 6 VSYNC 待つ → BGM 停止 → プログラム終了。

タイトルでは BGM は鳴らない。

### 3.5 ニューゲーム初期化
1. 所持品 260 組をすべて (0,0) にする。
2. スイッチ 0〜1000 をすべて 0。
3. 変数：96/06 版は 0〜49 だけ 0、他の版は 0〜99 を 0（20 §10.3 H）。
4. 主人公スプライト種別 ← 0（徒歩）。現在マップ ← 開始マップ番号（状態ブロック 0x283）。
5. CHR スロットとチップセットの「読込済み」記録を無効にする（次のマップ読込で必ず読み直す）。
6. 主人公・船・飛空艇のスプライトをパターンキャッシュに読む（§4.4）。
開始座標・向き（2）・乗り物・所持金・パーティ等は状態ブロックの初期値のまま。

## 4. マップの読込と進入

### 4.1 マップ読込（マップが変わった時だけ行う）
1. **グリッドとヘッダ**：MAPnnn.DAT を読む（20 §7.3）。160×160 の配列を、X または Y が大きさ N 以上の位置は外周チップ、範囲内はグリッド値で埋める。ファイルが無ければ既定マップ（20 §7.3）。
2. **グラフィック**：
   1. CHR スロット 0〜3 に、ヘッダの CHR 番号の CHRnnn.ECD（64 パターン）を読む。スロットごとに「読込済み番号」を覚えており、同じ番号なら読み直さない。CHR のパレットは捨てる。
   2. チップセット：番号が読込済み番号と違えば、MCPnnn.ECD（160 パターン）を読み、ファイルがあれば（48 バイト以上）そのパレットを **ベースパレット**と現在パレットに設定（表示更新はしない）。続いて MCPnnn.DAT から属性・エンカウント種別・戦闘背景を読み加工する（20 §8.2）。
   3. チップセット番号が同じでも違っても、パターンキャッシュのオートタイル素材（§4.4）にチップ 0〜3 のパターンを写す。
3. **イベント**：エンカウント区域表・マップ版数・イベント位置表・イベント領域を読み込む（20 §7.3.3〜7.3.5）。下層用・上層用の 2 枚の「イベント位置図」（160×160、値＝イベント番号、0xFF＝空き）を全部空きにする。イベント番号 0〜249 の順に、存在するイベントについて：
   1. 層 ← 足元チップの層属性が 0x20 または 0x60 なら 0x20、そうでなければ 0x00。
   2. 移動タイマ ← 乱数 % 40 ＋ 10（**イベント 1 個につき乱数 1 回**）。
   （この時点ではイベント位置図には登録しない。登録はページ更新 §7.2 で行う。）
4. 色調を即時に再適用（§2.4、種別＝状態ブロックの色調値−1、速度 −1）。

### 4.2 マップ進入処理
現在マップ番号・座標を決めてから呼ぶ（ニューゲーム、ロード、場所移動、ワープ、脱出、デバッグ開始）。
1. 現在マップ番号 ≠ 読込済みマップ番号なら、読込済み ← 現在マップ番号 とし §4.1 を行う。
2. ページ更新（§7.2）。
3. スクロール量 ← 0、歩数 ← 0。
4. ビュー原点（ビューの左上セルのマップ座標）：ループしないマップは (X−9, Y−6)（負やマップ外にもなる）、ループするマップは ((X+N−9) mod N, (Y+N−6) mod N)。
5. 主人公の層を足元チップから更新（§6.3）。
（描画・BGM 再生は呼び出し側が行う。）

### 4.3 パターン番号の空間
描画で使う「パターン番号」は次の 3 領域を指す：
- 0x00〜0x9F：チップセットのパターン（チップ番号と同じ）。
- 0xA0〜0xC0：パターンキャッシュ（33 個、§4.4）。
- 0xC1〜0xFF：空のパターン（全 0、何も描かれない）。
- 0x100 以上：CHR スロット。k ＝ 番号−0x100 として、スロット (k÷64) mod 4 のパターン k mod 64。

（注）イベントのグラフィック番号がマップチップ（0x01〜0x9F）でも、§5.5 の向き・コマの加算で 0xA0 以上になると、パターンキャッシュ（主人公・乗り物の絵など）や空パターンを指す。そのまま表のとおりに扱う。

### 4.4 パターンキャッシュ
| 番号 | 内容 |
|---|---|
| 0xA0〜0xA7 | 主人公（パーティ先頭）。順に 上0, 上1, 右0, 右1, 下0, 下1, 左0, 左1 |
| 0xA8〜0xAF | 船（同じ並び） |
| 0xB0〜0xB7 | 飛空艇（同じ並び） |
| 0xB8〜0xBB | チップ 0〜3 のパターン（オートタイル素材） |
| 0xBC〜0xC0 | 空（全 0） |

「キャラクタをキャッシュに読む（先頭位置 B、CHR 番号 f、開始パターン p）」：
1. B から 8 個を全 0 にする。
2. 読み元：現在のヘッダの CHR スロットのどれかが f で、かつそのスロットが f を読込済みならそのスロットの内容、そうでなければ CHRf.ECD を直接読む。
3. r＝0〜3（上・右・下・左）、c＝0,1 について、パターン p＋8r＋c（63 以下のもの）を B＋2r＋c に写す。

主人公の CHR はパーティ先頭のメンバー（先頭のメンバー番号が 11 を超えていればメンバー 0。パーティ人数が 0 でも並びの先頭の値を使う）の記録の 0x4B/0x4D、船・飛空艇は状態ブロックの値。全部を読み直すときの順序は 船 → 飛空艇 → 主人公。
読み直す時機：ニューゲーム（全部）、ロード（全部）、戦闘の後（全部）、仲間の加入・離脱と主人公グラフィック変更（主人公のみ）、乗り物グラフィック変更（乗り物のみ）、並び替えメニュー（主人公のみ）。マップ移動では読み直さない（キャッシュは独立したコピーなので不要）。

## 5. フィールド描画

### 5.1 画面とビュー
- フィールドは 32×32 ドットのセル単位。ビュー座標 (vx, vy) のセルは、スクロールずれ (dx, dy) を差し引いて画面の (16 + 32vx − dx, −16 + 32vy − dy) に描く。
- 描くセルは vy＝−1〜13、vx＝−1〜19 の範囲のうち、セルの矩形が X 16〜623・Y 0〜383 の範囲と重なるもの（左端 X が 624 以上のセルは描かない）。描いたセルの画素は X 16〜639・Y 0〜383 の範囲だけ書き、はみ出しは切り捨てる（X 624〜639 は下記のマスクで隠れるので、そこに残る絵は見えない）。
- テキスト層で枠を作る（「フィールド用マスク」）：テキスト層 80×25 全面を黒の不透明（属性 0x05 相当: 表示・反転・色なし）にし、桁 2〜77 × 行 0〜23 を透明（0xE1 相当）にする。結果として見えるのは X 16〜623、Y 0〜383（19×12 セル。上端と下端のセルは半分）。主人公のセル (9,6) は画面 (304,176)〜(335,207)、中心が (320,192)。
- **ビューは端で止まらない**。主人公は常に中央にいて、ループしないマップの外側は外周チップで埋まる。
- スクロールずれ：主人公が左へ移動中なら dx＝−(左の進み)、右なら dx＝+(右の進み)、下なら dy＝+(下の進み)、上なら dy＝−(上の進み)。ビュー原点は 1 歩が完了するまで動かない（§6.2）。
- 参照実装は描画のたびにビュー全体を描き直す（原本は変化したセルだけを描き直す最適化をしているが、最終的な画像は同じ）。

### 5.4 スプライトの重ね方
- スプライト（キャラクタ・イベントのグラフィック・乗り物）はパターンのマスクを使い、各プレーンを「下地 AND NOT マスク OR パターン」で重ねる（20 §8.1）。
- **セル単位の合成**：各セルは 32×32 の作業領域で独立に合成し、そのセルにかかる各スプライトのうち **そのセルの矩形内の部分だけ**を描く。したがって 1 体のスプライトが 2 セルにまたがるとき、それぞれの部分はそのセルの規則（覆いかぶさるチップ・橋）に従って描かれたり隠れたりする。
- 「位置ずれ (ox, oy) で描く」＝ スプライトの左上をセルの左上から (ox, oy) ずらして描き、セル外を切り捨てる。

### 5.5 イベントのグラフィック（パターン番号の決定）
ページのグラフィック番号 g（0 なら何も描かない）、アニメーション種別、向きの扱い、イベントの向き・向き固定から、描くパターン番号を次のように決める。A は自走カウンタ。
1. アニメーション種別が 0 または 1 のとき：
   1. 「向き別あり」＝（向きの扱いが 2 でない）または（向き固定が 1）。
   2. 向き別ありなら、g を 4 行ブロックの上向きの行に正規化：(g & 0x1F) が 15 を超えれば g−=16、続いて (g & 0x1F) が 7 を超えれば g−=8。
   3. 種別 0（足踏み）なら g ＝ (g の最下位ビットを 0 にしたもの) ＋ ((A ÷ 16) & 1)（16 VSYNC ごとに 2 コマ交互）。種別 1 は変えない。
   4. 向き別ありなら g に方向オフセットを足す：使う向き＝（向き固定が 2 以上ならその値、そうでなければイベントの向き）。オフセットは 向き 2→+16、4→+24、6→+8、8→+0、0→+84（使う向き÷2 を 5 で割った余りで引く表）。
2. アニメーション種別が 2 以上のとき：(g & 0x0F) が 7 を超えれば g−=8。t ＝（種別 2 なら (A÷16) & 3、それ以外（3 と、実データに無い 4 以上）なら (A÷8) & 3）として（種別 4 以上は種別 3 と同じ扱い。v1.1 で追記）、g に {0, 1, 8, 9} の t 番目を足す（2×2 の 4 コマを順に）。向きは無視。
3. 結果の g をパターン番号（§4.3）として描く。

（注）グラフィック番号 0x01〜0x9F（マップチップ）でも同じ加工を受ける。

### 5.6 イベント位置図
- 2 枚の 160×160 の図：**上層図**（層 0x00 のイベント）と **下層図**（層 0x20 のイベント）。値はイベント番号、0xFF＝空き、0xFD＝空き（消去・移動で空いた跡）。0xFA 以上はすべて空きとみなす。
- 位置 (x,y) の「イベント（全層）」＝ 上層図の値が有効（0xFA 未満で、そのイベントが存在）ならそれ、そうでなければ下層図の値が有効ならそれ、どちらも無ければなし。
- 「主人公と同じ層のイベント値」(ビュー座標指定、座標はマップ大きさ N で剰余を取る。ループしないマップでも剰余)：船がこのマップのその位置にあれば特別値「船」（1000）。そうでなければ、足元チップの層属性が 0x60 か主人公の層が 0 以外なら下層図、それ以外は上層図の値（空き値もそのまま返す）。ここでいう「足元チップ」は主人公の足元ではなく、**問い合わせ位置（指定したビュー座標を剰余したマップ座標）のチップ**のこと（正面のセルを問い合わせるときは正面のチップの層属性を見る）。（v1.1 で修正）
- 「主人公と別の層のイベント値」：船なら「船」、そうでなければ主人公の層が 0 なら下層図、0 以外なら上層図の値。

### 5.7 セル合成の手順
ビューセル (vx, vy) について：
1. マップ座標を求める。ループしないマップ：(ビュー原点＋vx, ビュー原点＋vy)。それがマップ外なら外周チップをチップとして描いて**このセルは終わり**（何も重ねない）。ループするマップ：N で剰余。
2. チップ c、属性 a を得て、チップを描く（§5.3）。
3. a に覆いかぶさりビット（0x10）があり、飛空艇に乗っていなければ、**このセルは終わり**（キャラクタ・イベント・乗り物を何も描かない）。
4. lvl ＝ a の層属性。E ＝ この位置のイベント（全層）。U・R・L・D ＝ 上・右・左・下の隣のイベント（全層。座標は N で剰余を取る。ループしないマップでも反対側の端を見る）。
5. 「通常層の描画（イベント X、位置ずれ）」とは：X が存在し、X の現在の有効ページ（§7.1、**描画のたびにその場で評価**）が −1 でなく、（lvl＝0x40 かつ X の層＝0x20）でなく、そのページのプライオリティが 2 でなければ、§5.5 のパターンを位置ずれで描く。「上層の描画」はプライオリティが 2 のものだけを描く（他の条件は同じ）。
6. **通常層**（a に 0x10 が無い場合のみ。飛空艇搭乗中に 0x10 のセルではここを飛ばす）：
   - E が存在し、E が移動中でなく（進み 0）、（lvl＝0x40 かつ E の層＝0x20）でなければ：E を位置ずれ (0,0) で通常層描画。
   - そうでなければ、次の 8 つを順に（該当する進みが 0 でないものだけ）通常層描画する。p はそのイベントのその方向の進み：
     1. E が下へ移動中：(0, p−32)
     2. U が上へ移動中：(0, −p)
     3. E が左へ移動中：(32−p, 0)
     4. R が右へ移動中：(p, 0)
     5. E が右へ移動中：(p−32, 0)
     6. L が左へ移動中：(−p, 0)
     7. E が上へ移動中：(0, 32−p)
     8. D が下へ移動中：(0, p)
7. **停泊中の船**：lvl が 0x40 でなく、船がこのマップのこの位置にあれば、キャッシュ 0xAA＋((A÷16)&1)（右向きの 2 コマ）を (0,0) に描く。
8. **停泊中の飛空艇**：飛空艇がこのマップのこの位置にあれば、キャッシュ 0xB2（右向き 1 コマ目、静止）を (0,0) に描く（橋でも描く）。
9. 飛空艇搭乗中なら、ここで上層（手順 11）を描く。
10. **主人公**（非表示フラグが 0 のとき）。f ＝ 飛空艇搭乗中なら 1、それ以外 0。主人公の基準セルはビュー (9, 6−f)（飛空艇では 1 セル上に描かれる）。
    - スクロール量が 0：基準セルに (0,0) で描く。
    - 移動中：基準セルに、上の進み p なら (0,−p)、右なら (p,0)、左なら (−p,0)、下なら (0,p) で描く。さらに移動先のセル（上なら (9,5−f)、下なら (9,7−f)、右なら (10,6−f)、左なら (8,6−f)）に、上 (0, 32−p)、下 (0, p−32)、右 (p−32, 0)、左 (32−p, 0) で描く。
    - 主人公の描画条件：lvl＝0x40 かつ 主人公の層＝0x20 かつ 飛空艇でない、ならこのセルには描かない（橋の下をくぐる）。
    - パターン：キャッシュ 0xA0 ＋ 主人公スプライト種別（0/8/0x10）＋ 方向の行（使う向き＝向き固定が 0 以外ならそれ、そうでなければ向き。2→+4、4→+6、6→+2、8→+0、0→+21）＋ コマ。コマは、徒歩なら (A÷16)&1（**立ち止まっていても足踏みする**）。船・飛空艇なら状態ブロックのアニメ種別で 0→(A÷16)&1、1→(A÷4)&1、2→0。
11. 飛空艇に乗っていなければ、ここで上層を描く。上層の描き方：E が存在し移動中でなければ E を (0,0) で上層描画、そうでなければ手順 6 の 8 つと同じ位置ずれで上層描画。

結果として：プライオリティ 0/1 のイベントは主人公の下、2 は主人公の上（飛空艇搭乗中は 2 も主人公の下）。1 セルに描かれる「その場のイベント」は E の 1 体だけ（上層図・下層図の両方にいる場合は上層図の方）。

## 6. 主人公の移動

### 6.1 1 歩の開始（方向 d、高速フラグ）
スクロール量が 0 のときだけ受け付ける。
1. 通行判定（§6.5）。不可なら終わり（向きは d に変わる）。
2. スクロール量 ← 高速なら 16、そうでなければ 8。
3. 主人公の X,Y を d 方向に 1 進める（N で剰余。ループしないマップでは判定で範囲外を弾くので剰余は効かない）。
4. 高速フラグを記録。方向別の進みのうち d の欄 ← スクロール量。
5. 層を新しい足元チップから更新（§6.3）。
6. 「主人公が動いた」← 1。

高速移動：飛空艇搭乗中のキー移動、およびイベントの「高速移動」命令（→ 22）。

### 6.2 1 歩の進行（3 VSYNC ごとの「主人公処理」）
1. イベント実行中かつスクロール量 0 なら、イベントの移動命令を 1 回処理する（§8.6。命令が 3 以上なら「主人公が動いた」← 0 にしてから）。
2. スクロール量が 0 なら、フィールドを描いて終わり（戻り値 0）。
3. イベント実行中でなければ：
   - 徒歩で、毒のメンバーがいれば：スクロール量が 24 なら T＝160 で表示更新し、パーティの毒状態のメンバーのうち HP が 1 より大きい者の HP を 1 減らす。スクロール量が 32 なら T＝100 で表示更新（§6.4）。
   - スクロール量が 32 なら「到着」とする。
4. フィールドを描く（その時点のスクロールずれで）。
5. スクロール量が 32 なら：ビュー原点を移動方向に 1 動かし（ループするマップは N で剰余）、スクロール量と進みを 0 にする。そうでなければスクロール量と進みに 8（高速なら 16）を足す。
6. 到着でなければ戻り値 0。
7. 到着なら（イベント実行中でないときだけ到着になる）：
   1. 徒歩なら歩数を 1 増やす。
   2. 「主人公と同じ層のイベント値」の位置 (9,6) のイベントを起動条件「重なる」で起動を試み（§7.3）、起動すれば戻り値 1。
   3. 「別の層のイベント値」でも同様。
   4. 乗り物に乗っていれば戻り値 0。
   5. エンカウント判定（§10）の結果を返す。

描かれるスクロール量の列は、通常 8, 16, 24, 32、高速 16, 32。1 歩の所要は通常 4 回（12 VSYNC）、高速 2 回（6 VSYNC）。スクロール量 32 の状態で描いた画面は、到着後の原点で 0 の状態と同じ絵になる。

### 6.3 層の更新
足元チップの層属性が 0x00 なら主人公の層 ← 0x00、0x20 なら 0x20、0x60 なら 0x60、0x40（橋）なら変えない。

### 6.4 毒の歩行ダメージ
§6.2 手順 3 のとおり。1 歩ごと（通常速度の歩行のみ。スクロール量 24 を通るのは通常速度だけ）に、毒のメンバーの HP を 1 減らす（HP 1 では減らない＝毒で死なない）。同時に画面が一瞬白っぽくなる（T＝160、次の主人公処理＝スクロール量 32 の処理で 100 に戻る＝T＝160 の表示は 3 VSYNC）。乗り物・イベント中は起きない。「毒のメンバーがいる」フラグはパーティの毒状態の変化時に再計算される（→ 22・23・24）。

### 6.5 通行判定（主人公、目標はビュー座標 (tvx, tvy)、方向 d）
1. 主人公の向き ← d（通れなくても向きは変わる）。
2. ループしないマップで、目標のマップ座標が範囲外なら不可。
3. 次の判定は「（非表示フラグが 0 またはイベント実行中でない）かつ 強制移動中でない」ときだけ行う。そうでなければ可（＝イベント中に非表示の主人公はどこでも通れる。強制移動もすべて通れる）。
4. A ＝ 足元チップの属性、B ＝ 目標チップの属性（ループしないマップの範囲外なら属性 0x0F として扱う）。
5. **徒歩**：次の「乗船例外」でなければ判定する。乗船例外 ＝ イベント実行中 かつ 目標の同層イベント値が「船」かつ 降船可能判定（徒歩用、§9.1）が可。
   1. 層の衝突：A の層属性が 0x60 でなく、かつ（主人公の層が 0 で B の層属性が 0x20、または 主人公の層が 0x20 で B の層属性が 0）なら不可（イベントは起動しない）。
   2. 「目標に通行不可のイベントがある」（§6.6）、または A の d 側の辺ビット、または B の反対側の辺ビット（20 §8.2.1）なら：目標の同層イベント値のイベントを起動条件「接触」で起動を試み（§7.3。値が空きや「船」なら何もしない）、不可。
   （辺ビットで塞がれている場合でも、そこにあるすり抜け可能なイベントが「接触」起動しうる。）
6. **船**：イベント実行中でない、または降船可能判定（船用）が不可のとき：目標に通行不可のイベントがあれば同層イベント値を「接触」で起動を試み不可。B に船通行ビット（0x80）が無ければ不可。辺ビットと層は見ない。
   イベント実行中で降船可能判定（船用）が可なら、その場で下船（§9.1 の下船処理、BGM は変えない）して可。
7. **飛空艇**：判定なし（常に可）。
8. 可。

### 6.6 目標に通行不可のイベントがあるか
目標マップ座標（N で剰余）の層属性 l を見て、l＝0 または（l＝0x40 かつ主人公の層＝0）なら上層図、それ以外なら下層図の値 i を取る。i が 250 以上なら無し。イベント i の現在の有効ページが −1 でなく、そのプライオリティが 0 なら「ある」。

### 6.7 強制移動
「強制移動中」← 1 にして向いている方向へ 1 歩の開始（§6.1、通常速度）を行い、「強制移動中」← 0。続けて方向キーのラッチを記録。船から降りる場合はさらに BGM 処理（§9.1）。

## 7. イベントのページと起動

### 7.1 有効ページの決定
ページ 3, 2, 1, 0 の順に見て、出現条件を満たす最初のページを有効ページとする：
- 種類 1（スイッチ）：番号が 1000 以下でそのスイッチがオン。
- 種類 2（アイテム）：そのアイテムを持っている（所持判定 → 22。ビルド差分 G）。
- 種類 3（仲間）：条件メンバー番号の下位バイトのメンバーがパーティにいる。
- 種類 4（お金）：所持金 ≥ 条件金額。
- **種類 0（条件なし）は、この探索では一致しない。**
どれも満たさなければ：ページ 0 の条件が 0 ならページ 0、そうでなければ −1（イベントは出現しない）。
→ ページ 1〜3 を「条件なし」にしても選ばれない。条件付きのページ 0 は条件を満たさないと −1。

### 7.2 ページ更新
次の時機に全イベントについて行う：マップ進入、戦闘の後、各イベント実行の終了時、いくつかのイベント命令の中（→ 22。ピクチャ表示命令では画像を読む**前**に 1 回）、フィールドメニューを閉じる時、ロード時（マップ進入の中）。**毎フレームではない**（描画・通行・起動・NPC の判定は有効ページをその場で評価するので、スイッチが変われば見た目は即座に変わるが、イベント位置図の登録・向きのリセットはページ更新まで行われない）。

イベント番号 0〜249 の順に、存在し完全消去済み（現在ページ＋1 が 9）でないイベントについて：
1. p ＝ 有効ページ。記録の「現在ページ＋1」が p＋1 と等しければ何もしない。
2. 「現在ページ＋1」が 0 でなければ（ページが変わった）向き ← 0。
3. 「現在ページ＋1」← p＋1。再描画要求を立てる。
4. p が −1 なら：イベント消去（§7.5、完全消去でない）を行い、「現在ページ＋1」← 0、有効フラグ ← 0。次のイベントへ。
5. 層が 0 なら上層図、そうでなければ下層図の (X,Y) に自分の番号を書く。
6. （再描画区分の設定。最適化用なので省略可。）
7. 移動の進みが 32 または向きが 0 なら、進みと方向別の進みを 0 にする（移動途中を打ち切る）。
8. 進みが 0 で向きが 0 なら、向き ← グラフィック番号のビット 3〜4 の値 r に対して {8, 6, 2, 4}[r]（ブロック内の行：上・右・下・左）。
9. 有効フラグ ← 1。

### 7.3 イベントの起動（イベント番号 i、起動種別 t）
起動種別 t：0＝調べる（正面）、1＝接触（主人公がぶつかる／NPC が主人公に触れる）、2＝重なって調べる（足元）、3＝重なる（主人公の到着／NPC が主人公の位置に来る）、4＝自動。
起動しない条件（どれか 1 つでも当てはまれば何もせず 0 を返す）：
1. 既にイベント実行中、または飛空艇搭乗中。
2. i が 0〜249 でない（空き値・「船」を含む）、またはイベントが存在しない。
3. イベントが移動中（進み ≠ 0）、または有効フラグが 0。
4. テストプレイ中で STOP（＋CTRL）が押されている。
5. （ここで、t＝1 かつ移動タイマが 0x18 未満なら移動タイマを 1 増やす。起動するかどうかに関係なく行う）
6. 有効ページが −1。
7. ページの起動条件が 1（接触）なら t が 0 か 1 でなければ不起動。それ以外の起動条件は t と等しくなければ不起動。（＝「接触」のページは調べても起動する。）
8. 徒歩で t が 1 以下、かつイベントの足元チップの層属性が 0x60 でないとき：イベントの層が 0 で主人公の層が 0x20、またはイベントの層が 0x20 で主人公の層が 0 なら不起動（主人公の層が 0x60 なら通る）。
9. ページのスクリプトが空（先頭バイトが 0）。

起動する場合：
1. 状態ブロックの「イベント番号」← i（スクリプト中の「このイベント」）。
2. 再描画区分を 0、イベント実行中 ← 1。現在のマップ戦闘 BGM 名を退避。
3. **振り向き**：表示パターンが 0 でなく、t が 2 未満、ページの向きの扱いが 0、かつ（移動タイプが 5 未満 または 保留中の起動種別が 0）なら、元の向きを退避してイベントの向き ← 10 − 主人公の向き（主人公と向き合う）。
4. フィールドを描く。
5. スクリプトを実行（→ 22。中で全滅を検出するとゲームオーバー → タイトルへ）。
6. 終了処理（§7.4）。戻り値 1（スクリプトの戦闘命令で逃走・敗北した場合は 2・3 → 22）。

### 7.4 イベント終了処理
1. マップ戦闘 BGM 名を退避した値に戻す（場所移動でマップが変わった場合は移動先の値が退避値になっている → 22）。
2. 振り向いていて、スクリプト中でこのイベント自身を動かしたり移動させたりしておらず、マップも変わっていなければ、向きを元に戻す。
3. 主人公の移動命令を 0、全イベントの移動命令と向き固定を 0 にする。**主人公の表示向き固定（状態ブロック 0x00F）はここでは消さない**（22 §6.6 の「全移動命令の解除」と同じ処理。主人公の向き固定を解除するのは移動命令 2 の設定だけで、固定したままイベントが終われば、以後の通常歩行でも固定された向きで描かれ続ける。値は状態ブロックの一部なのでセーブ・ロードで保存され、タイトルループで PLAYER.DAT の初期値に戻る）。（v1.1 で修正）
4. ページ更新。
5. 主人公が移動途中なら完了させる（→ 22 の「主人公の移動完了待ち」）。
6. メッセージウィンドウを閉じる。
7. イベント実行中 ← 0。キーバッファを空にする。

### 7.5 イベント消去（イベント i、完全消去かどうか）
1. 現在位置について：下層図が i なら 0xFD にし、さらに（97/03・97/10 版では）上層図も i なら 0xFD にする。下層図が i でなく上層図が i なら上層図を 0xFD にする。（旧版は下層図を消したら上層図を見ない → 20 §10.3 A）
2. 移動中なら、移動元の位置（下へ移動中なら Y−1、左なら X+1、右なら X−1、上なら Y+1。N で剰余）の両方の図で i の箇所を 0xFD にする。
3. 完全消去なら「現在ページ＋1」← 9、有効フラグ ← 0。そうでなければ「現在ページ＋1」← 0（次のページ更新で再評価されて再出現しうる）。

## 8. NPC（イベントの移動）

### 8.1 処理順
フィールドの 3 VSYNC 周期ごとに、イベント番号 0〜249 の順に「NPC 処理」を 1 回ずつ行う。各周期の始めに「処理済み」印を全部消し、同じ周期内で同じイベントを 2 度処理しない（§8.4 の割り込み処理で先に処理されたものは飛ばす）。メインループでは主人公処理（§6.2）の **後**、イベントの時間経過待ち（→ 22）では主人公処理の **前** に行う。

### 8.2 NPC 処理（イベント i）
1. 処理済みなら終わり。処理済みにする。
2. イベントが存在しない、有効フラグが 0、または有効ページが −1 なら終わり。
3. 進みが 0（停止中）のとき：イベント実行中でなければ移動タイマを 1 増やし（8 ビット、255 の次は 0）、35 を超えたら移動タイプに応じて移動を試みる（§8.3）。移動タイプ 0 は何もしない。
4. 進みが 32 のとき：進みと方向別の進みを 0 にする（1 歩完了）。イベント実行中でなく、移動タイプが 0 でなく、起動条件が 3（重なる）で、イベントの位置が主人公の位置と同じなら、保留中の起動種別 ← 3、保留イベント ← 自分の番号。
5. それ以外（8〜24）：進みと、0 でない方向別の進みに、8（高速なら 16）を足す。
6. 最後に、イベント実行中で進みが 0 なら、イベントの移動命令を 1 回処理する（§8.6）。

1 歩は「開始（進み 8）→16→24→32→0」で、開始から完了まで 4 周期。

### 8.3 移動タイプ
「1 歩試行（方向 d）」は §8.4。試行の成否は試行後の進みが 0 でないかで判定する。乱数は §13 の順に引く。

- **1・2 ランダム**：元の向きを覚える。乱数 r1 を引き、r1 & 3 が 0 でなければ乱数 r2 を引いて d ＝ (r2 & 3)×2＋2、0 なら d ＝ 現在の向き。1 歩試行。
  - 失敗：新版（97/03・97/10）は向きを元に戻す。旧版は戻さない（20 §10.3 C）。移動タイマはそのまま（35 超のままなので次の周期にまた試みる）。
  - 成功：移動タイマ ← タイプ 1 なら 乱数%10、タイプ 2 なら 乱数%4＋20。
  （次に動き出すまでの停止周期数は 36 − タイマ値：タイプ 1 は 27〜36、タイプ 2 は 13〜16。）
- **3 上下往復**：向きが上なら「上→下」、そうでなければ「下→上」の順に、最初の方向で 1 歩試行し、失敗なら 2 番目の方向で試行。成功なら移動タイマ ← 28（8 周期後に次の 1 歩）、2 方向とも失敗なら 0（36 周期後）。乱数は使わない。
- **4 左右往復**：同様に「左」と「右」（向きが左なら左を先に）。
- **5・6 接近**：主人公との差 dx ＝ 主人公X − X、dy ＝ 主人公Y − Y（剰余を取らない生の差）。|dx| < 9 かつ |dy| < 7 かつ主人公が徒歩なら、乱数 r を引き r%5 が：0〜1 なら d ＝ dx>0 なら 6、dx<0 なら 4、0 なら「なし」；2〜3 なら d ＝ dy>0 なら 2、dy<0 なら 8、0 なら「なし」；4 なら乱数をもう 1 回引いて (r & 3)×2＋2。条件を満たさなければ乱数を引いて (r&3)×2＋2。
  - d が「なし」なら何もしない（参照実装の処置。原本は未初期化の方向値を使う【未確認】）。移動タイマはそのまま。
  - 1 歩試行。成功なら移動タイマ ← タイプ 5 は 乱数%8＋20（停止 9〜16 周期）、タイプ 6 は 乱数%4＋28（停止 5〜8 周期）。失敗ならタイマはそのまま（次の周期に再試行）。

### 8.4 NPC の 1 歩試行（方向 d、高速フラグ）
1. 移動先 (tx, ty) ＝ 位置を d 方向に 1 進め N で剰余（ループしないマップでも剰余を取る）。ca ＝ 足元チップ、cb ＝ 移動先チップ、a・b ＝ その属性。
2. イベントの向き ← d（失敗しても振り向く）。
3. **地形判定**：「海規則」を使うのは（旧版、または チップ 0 の属性の下位 4 ビットが 0x0F）のとき（20 §10.3 B）。
   - 海規則を使い、かつ ca が 4 未満または 0xA0 以上のとき：cb が 4 以上 0xA0 未満なら失敗。そうでなければ辺ビットは見ずに次へ。
   - それ以外：a の d 側の辺ビット、または b の反対側の辺ビットが立っていれば失敗。
4. **障害判定**（結果：0 空き、1 塞がり、2 主人公がいる）：
   1. ループしないマップで、移動先が元の位置から X または Y に 2 以上離れている（端で反対側に回り込んだ）なら 1。
   2. 足元チップの層属性が 0x60 なら：b の層属性が 0 ならイベントの層 ← 0、0x20 なら ← 0x20、それ以外は変えない。そうでなく、（イベントの層 0 で b の層属性が 0x20）または（イベントの層 0x20 で b の層属性が 0）なら 1。
   3. 見る図 ＝（イベントの層が 0 以外 または b の層属性が 0x60）なら下層図、そうでなければ上層図。移動先の値 o が空き（0xFA 以上）か自分なら次へ。そうでなく、イベント実行中なら NPC 処理（§8.2）を o に対して先に行い（未処理なら）、もう一度 o を読み直して空きか自分なら次へ、まだ塞がっていれば 1。イベント実行中でなければ 1。
   4. 移動先が主人公の位置で、（主人公の非表示フラグが 0 またはイベント実行中でない）かつ（主人公の層が 0x60 またはイベントの層＝主人公の層）なら：ページのプライオリティが 0 なら 2、そうでなければ 0（すり抜けイベントは主人公に重なれる）。
   5. 移動先に（このマップの）船があれば 1、飛空艇があれば 1。
   6. 0。
5. イベント実行中でなく、移動タイプが 5 以上（接近）で、結果が 2 なら：移動タイマ ← 乱数%4＋20、向き ← d、保留中の起動種別 ← 1（接触）、保留イベント ← 自分の番号。
6. 結果が 0 なら：高速フラグを記録し、進み ← 8（高速 16）、d の欄の方向別の進み ← 進み。イベント位置図を更新（§8.5）。

### 8.5 イベントの位置の移動
1. 位置 ← 移動先。
2. 移動先チップの層属性が 0x60（連結）なら、イベントの層 ← 0x20 にし、上層図の移動先にも自分を書く。
3. 層が 0 なら上層図、そうでなければ下層図の移動先に自分を書く。
4. 移動元の位置の両方の図で、自分の番号の箇所を 0xFD にする。

### 8.6 移動命令（イベント実行中の主人公・イベントの動き）
イベント実行中、主人公（停止中）とイベント（停止中）は 3 VSYNC ごとに、設定された移動命令を 1 回処理する（命令の設定・解除は 22）。命令値 m：
- 0：何もしない。1・2：向き固定の設定・解除（設定時に処理済み。ここでは何もしない）。
- 3〜14：方向 ＝ (m÷3)×2（3〜5→下、6〜8→左、9〜11→右、12〜14→上）。m mod 3 が 0 なら向きを変えるだけ、1 なら 1 歩（通常速度）、2 なら 1 歩（高速）。主人公は §6.1（通行判定つき）、イベントは §8.4（有効ページがあるとき）。
- 15：時計回りに回転（3 回に 1 回）、16：反時計回りに回転（3 回に 1 回）、17：時計回りに回転（2 回に 1 回）。回転のカウンタは主人公用に 1 つ、**全イベント共通に 1 つ**あり、処理のたびに (カウンタ＋1) mod 3（17 は mod 2）とし、結果が 1 のときだけ回す（向きが 2/4/6/8 以外でカウンタは進む）。時計回り：下→左→上→右→下。反時計回り：下→右→上→左→下。向きが 2/4/6/8 以外なら回さない。2 つのカウンタは起動時に 0 で、以後ニューゲーム・ロード・イベント終了でも 0 に戻さない（参照実装の挙動）。
- 18 以上：何もしない。

## 9. 乗り物

### 9.1 船
- **停泊表示**：船のあるマップ・位置に、右向きの船を描く（§5.7 手順 7。橋のチップ上では描かない）。
- **乗る**：徒歩の主人公が船の位置に立つと乗船する。判定はメインループ（§11 手順 4）と、イベントの各種待ちループの中（→ 22）。乗船処理：乗り物 ← 1、主人公スプライト種別 ← 8、船のマップ ← 0xFFFF、直前 BGM ← 現在 BGM。メインループでの乗船時だけ、現在 BGM が船 BGM と違えば現在 BGM ← 船 BGM にして再生（待ちループ内の乗船では BGM を変えない）。
  - 船のチップ（海）は通常徒歩で入れないので、実際は正面に船があるとき決定キーで乗る：正面の同層イベント値が「船」で、降船可能判定（徒歩用）が可なら、強制移動で船の位置へ 1 歩進む（到着後に乗船）。
- **降船可能判定**（向いている方向 d が 2/4/6/8 以外なら常に可）：
  - 徒歩用：足元チップの d 側の辺ビットが立っていれば不可。正面に通行不可のイベント（§6.6）があれば不可。それ以外は可。
  - 船用：正面のチップの d の反対側の辺ビットが立っていれば不可。正面に通行不可のイベントがあれば不可。可の場合、**主人公の層 ← 正面チップの層属性が 0 以外なら 0x20、0 なら 0x00** にする。
- **降りる**（船上で決定キー、飛空艇が主人公と同じ位置（このマップ）に無く、降船可能判定（船用）が可のとき。§11 手順 4.7.3）：
  1. 下船処理：乗り物 ← 0、主人公スプライト種別 ← 0、船のマップ・位置 ← 現在のマップ・主人公の位置、歩数 ← 0。
  2. 強制移動で 1 歩進む（§6.7）。
  3. 直前 BGM と現在 BGM が違えば：現在 BGM ← 直前 BGM、直前 BGM ← 船 BGM にして再生。
- **移動**：§6.5 手順 6（船通行ビットのあるチップのみ。チップ 0〜3 とオートタイル）。エンカウントしないが、「重なる」イベントは起動する。メニューは開ける。

### 9.2 飛空艇
- **停泊表示**：§5.7 手順 8。
- **乗る（離陸）**：徒歩で飛空艇と同じ位置に立ち決定キー（足元イベントの「重なって調べる」が起動しなかった場合）。ただし足元チップが橋（0x40）で主人公の層が 0 以外なら乗れない。離陸処理：
  1. 乗り物 ← 2、主人公スプライト種別 ← 0x10、飛空艇のマップ ← 0xFFFF、向き ← 6（右）、非表示フラグ ← 0。
  2. 待ちカウンタを 0 にし、i＝0〜8 について：待ちカウンタが 3i になるまで待ち、主人公を描かずにフィールドを描き、飛空艇の絵（キャッシュ 0xB2）を画面 (304, 176−4i) に直接描く（マスク 1 の画素だけをパターンの色で描く。マスク 0 の画素は触らない）。
  3. 影の点滅を開始（§9.3）。方向キーのラッチを記録。フィールドを描く。
  4. 直前 BGM ← 現在 BGM。現在 BGM が飛空艇 BGM と違えば現在 BGM ← 飛空艇 BGM にして再生。
- **飛行中**：主人公（飛空艇の絵）はビュー (9,5)＝画面 (304,144) に描かれ、影が (9,6) の位置に出る。キー移動は高速（1 歩 6 VSYNC）。通行判定なし（ループしないマップの範囲外へは出られない）。イベントは一切起動しない（§7.3）、エンカウントしない、メニュー（ESC）は開けない。覆いかぶさるチップの上でも主人公は描かれる（そのセルでは通常層＝プライオリティ 0/1 のイベントは描かれないが、プライオリティ 2 のイベントと停泊中の船・飛空艇は描かれる。§5.7）。上層（プライオリティ 2）のイベントも主人公の下に描かれる。
- **降りる（着陸）**：飛行中に決定キー。
  1. 着陸不可 ＝ 足元チップの属性の下位 4 ビットが 0x0F、または 0x10（覆いかぶさる）を含む、または足元に何かイベントがある（全層）、または足元に船がある。
  2. 影の点滅を止め、影の位置のテキストを空白（透明）にする。
  3. 待ちカウンタを 0 にし、i＝0〜8 について：カウンタが 3i になるまで待ち、主人公を描かずにフィールドを描き、飛空艇の絵を (304, 144+4i) に描く（下降）。
  4. 歩数 ← 0。
  5. 着陸不可なら：同様に (304, 176−4i) で上昇アニメーション、影の点滅を再開、フィールドを描いて終わり（飛行を続ける）。
  6. 着陸：乗り物 ← 0、主人公スプライト種別 ← 0、飛空艇のマップ・位置 ← 現在のマップ・主人公の位置、向き ← 2、主人公の層 ← 足元の層属性が 0 か 0x40 なら 0x00、それ以外 0x20。直前 BGM と現在 BGM が違えば現在 BGM ← 直前 BGM にして再生。フィールドを描く。

### 9.3 飛空艇の影
飛行中、毎 VSYNC、影カウンタを (＋1) mod 3 で進め、カウンタが 0 以外なら テキスト層の桁 39・行 12（画面 (312,192)〜(327,207)）に外字の影（SJIS 0xEBB3、属性 0x01＝黒で表示）、0 なら空白 2 桁を書く（3 VSYNC 中 2 VSYNC 表示＝ちらつきによる半透明）。

### 9.4 乗り物の BGM のまとめ
| 場面 | 処理 |
|---|---|
| 船に乗る（メインループ） | 直前 ← 現在；現在≠船BGM なら 現在 ← 船BGM・再生 |
| 船に乗る（イベント待ち中） | 直前 ← 現在（再生しない） |
| 船から降りる（決定キー） | 直前≠現在 なら 現在 ← 直前、直前 ← 船BGM、再生 |
| 船から降りる（イベントの移動中） | BGM 変更なし |
| 飛空艇に乗る | 直前 ← 現在；現在≠飛空艇BGM なら 現在 ← 飛空艇BGM・再生 |
| 飛空艇から降りる | 直前≠現在 なら 現在 ← 直前・再生 |

BGM 名の比較は 9 バイト（8 文字＋NUL）。BGM の再生は「名前（最大 8 文字）の DAT_BGM/名前.MML を最初から再生。無ければ無音」（→ 02）。同名でも再生要求すれば最初から鳴り直すので、比較してから呼ぶ。
- BGM 名に SJIS の非 ASCII（例「戦闘」）が含まれる場合：参照実装は SJIS のバイト列をそのままファイル名として探し、ディスク上の項目名（UTF-8）とは ASCII 英字の大文字化だけで比較する（01 §6.1）。そのため、サンプルのようにファイル名が UTF-8 に変換されている環境では**見つからず無音**になる（確認例: fant1_8 で MAP026〜029 の戦闘 BGM「戦闘」→ `DAT_BGM/戦闘.MML` が見つからない）。原作（DOS）では SJIS 名のファイルが見つかって演奏されるので、クリーン実装は「SJIS のまま探し、無ければ名前を UTF-8 に変換して（または 01 §6.1 の推奨どおりディスク上の名前を SJIS に変換して）探す」改良を行ってよい。ただしその場合、該当場面の音は 参照実装の参照出力（無音）と一致しなくなる。（v1.1 で追記）

## 10. エンカウント

### 10.1 判定（徒歩で 1 歩到着し、「重なる」イベントが起動しなかったとき）
1. 敵出現オフ（状態ブロック 0x06E）なら出ない。
2. 区域 (X÷16, Y÷16) の 8 組を j＝0〜7 の順に見て、グループ番号が 0xFF でなく、条件が 0xFFFF または（1000 以下のスイッチ番号でそのスイッチがオン）のグループを候補リストに順に加える。候補 0 個なら出ない。
3. 率 R ＝ マップヘッダのエンカウント率。足元チップのエンカウント種別が 0 なら出ない、2 なら R ← R÷2、3 なら R ← R÷3（切り捨て）。
4. S ＝ 歩数（この歩を含む）。
   - R < S のとき：R÷2 ≥ 2 なら乱数を引き、乱数 % (R÷2) ≠ 0 なら出ない。
   - そうでなく R÷4 < S のとき：R ≥ 2 なら乱数を引き、乱数 % R ≠ 0 なら出ない。
   - それ以外：S < 5 なら出ない。R×2 ≥ 2 なら乱数を引き、乱数 % (R×2) ≠ 0 なら出ない。
   （各「≥ 2」の条件を満たさないときは乱数を引かずに「出る」へ進む。例えば R＝0 なら毎歩出る。）
5. 主人公の位置に船があれば出ない（乱数は消費済み）。
6. 歩数 ← 0。乱数 r を引く。戦闘背景番号 ← 足元チップの戦闘背景番号。候補リストの r % 候補数 番目のグループで戦闘開始（§10.2、ゲームオーバーあり）。戻り値（1 勝利／2 逃走／3 敗北）を返す。

例：R＝20 なら、歩数 1〜4 は出ず、5 は 1/40、6〜20 は 1/20、21 以上は 1/10。

### 10.2 戦闘の呼び出し（グループ、ゲームオーバーの有無、勝利時に消すイベント）
1. マップ戦闘 BGM 名と現在 BGM 名を 8 文字で比べ、違えば戦闘 BGM を再生。
2. 戦闘を実行（→ 24。戦闘開始時に歩数 ← 0）。結果：1 勝利、2 逃走成功、3 敗北（「ゲームオーバーなし」の戦闘のみ。「ゲームオーバーあり」の戦闘で全滅すると 24 の手順で全滅メッセージ → ブラックアウト（速度 2）→ **タイトルへ戻る**）。
3. CHR スロットとチップセットの読込済み記録を無効にし、マップのグラフィックを読み直す（パレットもチップセットのものに戻る）。主人公・乗り物のスプライトも読み直す。
4. 勝利で「勝利時に消すイベント」が指定されていれば、そのイベントを完全消去（§7.5）。
5. ページ更新。フィールド用マスクを設定。色調を即時に再適用（速度 −1）。フィールドを描く。1 VSYNC 待ち、T＝100 で表示更新。
6. マップ戦闘 BGM と現在 BGM が 8 文字比較で違えば現在 BGM を再生。
7. 結果を返す。

ランダムエンカウントは「ゲームオーバーあり」「消すイベントなし」。イベントからの戦闘（→ 22）は種類により異なる。

## 11. フィールドのメインループ

開始時：T＝0 で表示更新 → フィールド用マスクを設定 → フィールドを描く → ブラックイン（速度 1）→ キーバッファを空にする。

以下を無限に繰り返す（抜けるのはタイトルへ戻る／終了のときだけ）。
1. 方向キーのラッチを記録。
2. 自走カウンタが「前回この手順で記録した値」と等しい間だけ VSYNC を待ち、今回の値を c として記録する。前回の値の初期値（メインループ開始時）は 0。
   - したがって、前回からの間に他の処理（イベント・メニュー・戦闘・開始時のブラックイン等）で VSYNC が進んでいれば **1 VSYNC も待たずに**進む。また自走カウンタが 0 に戻された場合（§1.1）も、記録値と異なれば待たない。
   - 3 VSYNC 周期の判定は「その時点の c が 3 の倍数か」だけで行うので、他の処理の間に 3 の倍数を通り過ぎた周期は飛ばされる（追いつき処理はない）。
3. c が 3 の倍数なら（3 VSYNC 周期の処理）：
   1. c が 81 の倍数なら乱数を 1 回引いて捨てる。
   2. 主人公処理（§6.2）。戻り値が 0 でなければ（到着でイベントか戦闘が起きた）手順 1 へ戻る。
   3. 全 NPC 処理（§8.1）。
4. スクロール量が 0 なら：
   1. e1 ＝ 主人公の位置の同層イベント値、e2 ＝ 別層イベント値（§5.6）。
   2. 徒歩で e1 が「船」なら乗船（§9.1、BGM 処理つき）。
   3. 保留中の起動種別が 1 なら保留イベントを「接触」で、3 なら「重なる」で起動を試み、保留を 0 にする。起動したかを「起動あり」に記録。
   4. **自動イベント**：イベント 0〜249 を順に起動条件「自動」で起動を試みる。1 つでも起動したら「起動あり」とし、1 つも起動しない周回が来るまで 0〜249 の周回を繰り返す。
   5. キーを 1 個取り出し、キーバッファを空にする。
   6. キーが ESC で、乗り物が徒歩か船なら、フィールドメニュー（→ 23）を開き「起動あり」とする。
   7. 「起動あり」でなく、キーが SPACE か RETURN なら：
      1. e1 を「重なって調べる」で起動を試み、起動したら手順 1 へ。e2 も同様。
      2. 正面（向いている方向の隣、ビュー (9±1, 6±1)）の同層イベント値を e1、別層イベント値を e2 とする。
      3. 次のうち最初に当てはまるもの 1 つを行う：
         - 飛空艇がこのマップの主人公の位置にある：徒歩で、かつ（足元が橋で主人公の層が 0 以外）でなければ離陸（§9.2）。離陸条件を満たさなくても（例: 船で飛空艇の位置にいる）この項目に当てはまった時点で他の項目は行わない。
         - 船に乗っていて降船可能判定（船用）が可：降りる（§9.1）。
         - 飛空艇に乗っている：着陸（§9.2）。
         - 正面の e1 が「船」で降船可能判定（徒歩用）が可：強制移動で 1 歩（船へ乗りに行く）。
         - それ以外：e1 を「調べる」で起動を試み、起動したら手順 1 へ。e2 も同様。
5. 「起動あり」なら手順 1 へ。
6. 方向読み取り（§1.3）が 2/4/6/8 なら、その方向へ 1 歩の開始（§6.1。飛空艇搭乗中は高速）。

補足：
- 決定キーで調べる対象は「足元（重なって調べる）→ 正面（調べる）」の順。正面の「接触」ページも「調べる」で起動する（§7.3 手順 7）。
- 移動中（スクロール量 ≠ 0）はキーバッファを読まない（溜まったキーは停止後に 1 個だけ使われ、残りは捨てられる）。
- 方向キーは押している状態を毎フレーム見るので、押し続ければ連続して歩く（1 歩 12 VSYNC）。
- 手順 3.2 で主人公処理が 0 以外を返したときは、その周期の NPC 処理も手順 4 以降も行わずに手順 1 へ戻る。

## 12. イベント実行中のフィールド
イベントのスクリプトが待ちを伴う命令（移動完了待ち、時間経過、キー待ち等 → 22）を実行している間も、3 VSYNC ごとに「全 NPC 処理 → 主人公処理」（この順）が行われ、移動命令に従って主人公・イベントが動く。その間、§6.2 の到着処理（歩数・重なりイベント・エンカウント・毒）は行われない。乗船判定（BGM なし）は行われる。

## 13. 乱数

### 13.1 生成法
- 32 ビットの内部状態 s。1 回引くごとに s ← (s × 0x015A4E35 + 1) mod 2³² とし、(s >> 16) & 0x7FFF（0〜32767）を返す（Borland Turbo C の rand と同じ）。
- 種：原本は起動時に時計から設定する。参照実装は現在時刻（秒）を種にし、テスト用に固定種（ヘッドレス実行器の既定は 1）を指定できる。クリーン実装も固定種を指定できるようにすること。
- 「乱数 % n」は 0〜32767 の値を n で割った余り。

### 13.2 本章の範囲での使用箇所（引く順序）
| 箇所 | 回数 | 使い方 |
|---|---|---|
| キー待ち（§1.3）のポーリング毎 | 1 回／約 2ms | 捨てる（人の操作時間で消費数が変わる＝実質的な種のかき混ぜ） |
| マップ読込（§4.1） | 存在するイベント 1 個につき 1 回（番号順） | 移動タイマ ＝ 乱数%40＋10 |
| メインループ（§11 手順 3） | 自走カウンタが 81 の倍数の周期に 1 回 | 捨てる |
| 主人公の到着 → エンカウント（§10.1） | 0〜1 回（確率判定）＋ 出る場合 1 回（グループ選択） | 本文どおり |
| NPC ランダム移動（§8.3） | 1 回（＋1 回で方向）＋成功時 1 回（タイマ） | 本文どおり |
| NPC 接近（§8.3） | 1〜2 回＋成功時 1 回 | 本文どおり |
| NPC が主人公に触れた（§8.4 手順 5） | 1 回 | タイマ ＝ 乱数%4＋20 |

1 周期内の順序：（81 の倍数なら捨て 1 回）→ 主人公処理（到着時のイベント → エンカウント）→ NPC 処理（番号順、割り込みあり）。他の使用箇所：イベントの乱数命令（→ 22）、メニューの魔法効果（→ 23）、戦闘（→ 24）。

## 受け入れテスト観点
1. 起動・タイトル：TITLE.DAT のあるゲーム（keep 等）で、通常モードではタイトル画像がブラックイン（約 18 VSYNC）→キー待ち→ブラックアウトし、緑等の背景（TITLE パレットの色 14）にメニューが出る。テストプレイモードではタイトル画像を出さずにメニューが出る。
2. 「ゲーム終了」で終了、「コンティニュー」で SAVE ファイルの無いスロットを選ぶとメニューに戻る。
