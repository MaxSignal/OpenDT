# 20. Dante98 II（D2）データ形式・セーブ形式・RPG.EXE ビルド判別

## この章の範囲

- チップ属性のビット定義。

## 表記
- 数値はすべてリトルエンディアン。u8/u16LE/u32LE/i16LE は符号なし／符号付き整数。
- 「文字列SJIS[n]」は n バイト固定長の Shift_JIS 文字列。NUL（0x00）で終わる。n バイトすべてが文字で埋まり NUL が無い場合もあり、その場合は次のフィールドの先頭まで読み進めてしまう（後述の WORD.DAT の注意を参照）。
- 「メンバー番号」はパーティ記録（主人公）の番号 0〜11。
- 方向値は 2＝下、4＝左、6＝右、8＝上（テンキー配置）。0 は「未設定」。

## 1. ゲームディレクトリ構成

ゲームルートは RPG.EXE を含むディレクトリ。D2 ゲームの判定条件は「`DAT_RPG/PLAYER.DAT` が存在し、かつ `DAT_MAP` がディレクトリである」こと（D1 はルート直下に PLAYER.DAT・MAP00.DAT 等を持つので区別できる → 01_platform_common.md のゲーム判別）。

**ファイル名・フォルダ名は大文字小文字を区別せずに探すこと。** 実データには小文字のファイル（例: 05yakata の `save1.dat`）がある。パス区切りは `/` でも `\` でもよい。

| フォルダ／ファイル | 内容 | 読み込み時期 | 必須 |
|---|---|---|---|
| `RPG.EXE` | 原本の実行ファイル。**実行はしない**。ビルド判別にのみ読む（§10） | 起動時 | 無ければ 1997-10 版扱い |
| `MUSIC.COM` | 原本の音源ドライバ。読まない（互換ドライバを使う → 02） | — | — |
| `SOUND.DAT` | 効果音定義テキスト（→ 02） | 起動時（ドライバ） | 任意 |
| `*.BAT` | 起動用バッチ（`MUSIC -R` / `RPG` / `MUSIC -R`）。読まない | — | — |
| `SAVE1.DAT`〜`SAVE4.DAT` | セーブファイル（§9） | ロード時 | 任意 |
| `DAT_RPG/PLAYER.DAT` | 主人公 12 人の記録＋ゲーム開始時の状態ブロック（§2） | 起動時 | 必須 |
| `DAT_RPG/ITEM.DAT` | アイテム 256 件（§3） | 起動時 | 必須 |
| `DAT_RPG/MAGIC.DAT` | 魔法（特技）256 件（§4） | 起動時 | 必須 |
| `DAT_RPG/ENEMY.DAT` | 敵 256 件＋敵グループ 256 件（§5） | 起動時 | 必須 |
| `DAT_RPG/WORD.DAT` | 用語・システムメッセージ（§6） | 起動時 | 必須 |
| `DAT_RPG/GAIJI.DAT` | 外字 256 字（§7.2） | 起動時 | 必須 |
| `DAT_RPG/MAPNAME.DAT` | マップ名 1000 件（§7.1）。ワープ先一覧の表示に使う | 起動時 | 任意（無ければ全部空文字） |
| `DAT_RPG/TITLE.DAT` | タイトル画像（§8.4） | 起動時 | 任意（無ければタイトル画像なし） |
| `DAT_RPG/BTEST.DAT` | エディタの戦闘テスト設定（920 バイト）。**プレイヤーは読まない** | — | — |
| `DAT_RPG/EDITOR.DAT` | エディタの状態（4 または 8 バイト）。**プレイヤーは読まない** | — | — |
| `DAT_MAP/MAPnnn.DAT` | マップ（§7.3）。nnn はマップ番号の 10 進 3 桁ゼロ埋め（000〜999） | マップ進入時 | 任意（無ければ既定マップ） |
| `DAT_MCP/MCPnnn.DAT` | チップセットの属性表（§8.2） | マップ進入時 | 任意 |
| `ECD_MCP/MCPnnn.ECD` | チップセットのパターン 160 個＋パレット（§8.1） | マップ進入時 | 任意 |
| `ECD_CHR/CHRnnn.ECD` | キャラクタ（歩行グラフィック等）パターン 64 個（§8.1） | マップ進入時／スプライト更新時 | 任意 |
| `EGD_ENS/ENSnnn.EGD` | 敵画像 S サイズ（80×96）（§8.3） | 戦闘開始時 | 任意 |
| `EGD_ENL/ENLnnn.EGD` | 敵画像 L サイズ（160×128）（§8.3） | 戦闘開始時 | 任意 |
| `EBD_BKG/BKGnnn.EBD` | 戦闘背景 640×128（§8.5） | 戦闘開始時 | 任意 |
| `EBD_PCT/PCTnnn.EBD` | ピクチャ（全画面画像）（§8.4） | イベント「ピクチャ表示」時 | 任意 |
| `DAT_BGM/名前.MML` | BGM。名前は最大 8 文字の英数字。宿屋では固定名 `INN` を使う | 再生要求時 | 任意（無ければ無音） |

- 番号 nnn の書式は「最低 3 桁のゼロ埋め 10 進」。番号フィールドは u16 なので 1000 以上の値は 4 桁以上になる（例: 番号 1000 → `CHR1000.ECD`）。そのようなファイルは通常存在せず、「存在しない」扱いになる。
- 必須ファイルが無い場合、参照実装は「`DAT_RPG/ITEM.DAT が読み込めません.`」の形式でエラー終了する（メッセージ文言は 参照実装独自。原本の文言は【未確認】）。
- 実データには上記以外のファイル（`DAT_MAP/MCP000.DAT` の置き忘れ、`AUTOEXEC.BAT`、`*.PIF`、`readme.txt`、`ECD_CHR` の下の誤ったサブフォルダ等）が混ざることがある。プレイヤーはファイル名で直接開くだけなので無視すればよい。フォルダを列挙して処理する実装にしないこと。

## 2. PLAYER.DAT

サイズ 3080 バイト（0xC08）＝ パーティ記録 200 バイト × 12（0x000〜0x95F）＋ 状態ブロック 0x2A8 バイト（0x960〜0xC07）。

ファイルが短い場合、200 バイトが**完全に**読めたパーティ記録だけを使い（途中で切れた記録は全部ゼロのまま）、残りはゼロのままとする（状態ブロックはファイル長が 0x960+0x2A8 以上のときだけ読む。足りなければ全 0 に上書き 2 箇所を適用したもの）。

### 2.3 派生値の計算

ニューゲーム開始時とロード時に全 12 人について「再計算」を行う。装備変更・レベル変化時にも行う。

**(1) レベル L に必要な累積経験値 E(L)**（64 ビット整数、除算は 0 方向への切り捨て）
1. L < 2 なら 0。
2. L が 99 を超えるなら 99 として扱う。
3. a = L + 2。
4. t = ((a×a + 23) × (a × (a − 4))) ÷ 111 + 1。
5. f = (B − 10) × a + (A + 5) × 100 （A, B は 0x68, 0x69 の u8。B − 10 は負になりうる）。
6. E(L) = t × f ÷ 100 + C （C は 0x6A）。

例: A=8, B=8, C=0 で E(2)=12（Ring の空き記録の値と一致）。

**(2) レベル L の能力値 S(L)**（基礎値 b＝0x6B 系、成長量 g＝0x77 系、K＝0x66）
1. K < L の場合：S = b + 〔g×(K−1) を 16 ビット符号付きに切り詰めた値〕÷10 + g×(L−K)÷20。
2. それ以外：S = b + g×(L−1)÷10。
3. 上限で頭打ち（最大HP 9999、最大MP 999、4 能力 999）。下限の補正はない。
4. 結果を 16 ビット符号付きに切り詰める。
（÷ はすべて 0 方向への切り捨て）

**(3) 再計算の手順**
1. 現在レベルが最大レベル以上なら最大レベルにする。
2. 最大HP・最大MP・素の 4 能力を (2) で求める。
3. 次レベル経験値 ＝ 現在レベルが最大レベルなら 0、そうでなければ E(現在レベル＋1)。
4. 装備込み能力値 ＝ 素の能力値 ＋ 装備 5 箇所（0xFF 以外）のアイテムの能力補正（§3 の 0x1A〜0x21）の合計（16 ビットで加算）。その後 0〜999 に制限。
5. 習得済み魔法スロット i が魔法リストのスロット i と異なる値なら 0xFF にする（不整合の掃除）。
6. 現在 HP・MP は変更しない（レベルダウン時のみ最大値で頭打ち → 22）。

**比較の注意**：(4)(5) の「経験値 ≥ E」「経験値 < E」は、E を **符号なし 64 ビット**に読み替えて比較する。パラメータ A・B が小さいと高レベルで f が負になり E(L) が負になりうるが、その場合 E は非常に大きな値として扱われる（＝そのレベルへは上がらない、そのレベルにいれば下がる）。実データでは起きない。

**(4) レベルアップ**：現在レベル ≠ 最大レベル かつ 経験値 ≥ E(現在レベル＋1) の間、レベルを 1 上げ、習得レベルが新レベルに等しいスロットの魔法を習得する（習得方法はビルド差分 D、§10.3）。終わったら (3) を行う。
**(5) レベルダウン**：現在レベル > 0 かつ 経験値 < E(現在レベル) の間、レベルを 1 下げる。(3) を行い、現在HP/MP を最大値で頭打ち。

## 7. マップ関連

### 7.1 MAPNAME.DAT（任意）
16 バイト × 1000 件（16000 バイト）。件 i はマップ番号 i の名前（文字列SJIS[16]、16 バイト使い切りあり＝その場合は 16 バイトで打ち切る）。ワープ地点一覧の表示に使う（→ 23）。ファイルが無い・短い場合、足りない件は空文字。テストプレイ時のメニューに出るマップ名はこれではなく、マップファイルのヘッダ内の名前（§7.3）。

### 7.2 GAIJI.DAT
8224 バイト ＝ 32 バイトのヘッダ ＋ 32 バイト × 256 字。
- ヘッダ：先頭 `BFNT` 0x1A、+0x08 u16 幅=16、+0x0A u16 高さ=16、+0x0C u16 開始コード=0、+0x0E u16 終了コード=0xFF、残り 0。プレイヤーはヘッダを検査しない。
- 字 c（0〜255）のデータはオフセット 32 + 32c から 16 行×2 バイト。各行は **上位バイトが先**（ビッグエンディアン）の 16 ビットで、最上位ビットが左端のドット。
- SJIS で JIS 第 1 バイトが 0x76 の字は外字 (第 2 バイト & 0x7F)、0x77 の字は外字 0x80 + (第 2 バイト & 0x7F) を表示する（描画規則・太字化は → 01）。システムが使う外字：カーソル ▶（SJIS 0xEB9F）、ページ送り ◀▶（0xEBB4/0xEBB5）、キー待ち ▼（0xEBB7）、飛空艇の影（0xEBB3）。

### 7.3 MAPnnn.DAT

全体構成：

|---|---|---|
| 0x0000 | 0x28 | ヘッダ |
| 0x0028 | 4 | エディタのスクロール位置（i16LE X, i16LE Y）。プレイヤーは事実上使わない（マップ進入時に主人公位置から計算し直すため） |
| 0x002C | N×N | グリッド（N＝ヘッダの大きさ。行優先、1 バイト＝チップ番号） |
| 0x002C+N² | 0x960 | エンカウント区域表 |

実データではファイル末尾にこれ以外のデータは無い（D2 サンプル 23 本の全 3176 マップで検証）。

ファイルが 0x2C バイト未満（存在しない場合を含む）のときは **既定マップ**：大きさ 32、外周チップ 0、チップセット 0、CHR スロット＝状態ブロックの既定 CHR ×4、エンカウント率 20、戦闘 BGM＝状態ブロックの既定戦闘 BGM、マップ名空、ループなし、グリッド全 0、イベントなし、エンカウント区域なし（全 0xFF）。このとき **マップ版数は書き換えられず、直前に読んだマップの値のまま**になる（参照実装の挙動。セーブ時にはその値が書かれる）。

ファイルが 0x2C バイト以上でも途中で切れている場合は、グリッド・区域表・版数・イベント領域サイズ・位置表・イベント領域をこの順に読める所まで読み、読めなかった部分は初期値（グリッドは 0、区域表は 0xFF、位置表は 0xFFFF、イベント領域は 0）のまま。読み込みは **バイト単位**で、2 バイトの欄の途中で切れていれば下位バイトだけが書き換わる。**マップ版数には初期値が無い**：版数の欄のうちファイルに無いバイトは書き換えられず、既定マップと同じく直前に読んだマップの版数（起動直後で一度も読んでいなければ 0）のバイトがそのまま残る。イベント領域サイズは読む前に 0 に初期化される。（v1.1 で追記）位置表の値がイベント領域（32000 バイト）内に 0x62 バイトのイベント記録を収められない位置を指す場合、そのイベントは存在しないものとして扱う。

#### 7.3.2 グリッド
N×N バイト。値はチップ番号：
- 0x00〜0x03：特殊チップ（海など）。船で通行可能、オートタイルの素材。
- 0x04〜0x9F：通常チップ。
- 0xA0〜0xBF：グリッドには現れない（表示上はパターンキャッシュを指す）。
- 0xC0〜0xFF：オートタイル（チップ 0〜3 の 1/4 片を組み合わせた境界付きタイル）。属性・エンカウント種別・戦闘背景はチップ 0 と同じ扱い。実データでは 0xC0〜0xEC（インデックス 0〜44）が使われる。描画は 21 §5.3。

メモリ上は 160×160 の配列に置き、N 以上の X または Y の位置には外周チップを入れる。

#### 7.3.3 エンカウント区域表（0x960 バイト）
マップを 16×16 タイルの区域に分けた 10×10 区域。区域 (zx, zy)（zx = X÷16、zy = Y÷16）のレコードはオフセット zy×0xF0 + zx×0x18 の 24 バイト：

| 区域内オフセット | サイズ | 型 | 意味 |
|---|---|---|---|
| 0x00 | 16 | u16LE×8 | 出現条件 j（j=0〜7）：0xFFFF＝常に、0〜1000＝そのスイッチがオンのとき、それ以外＝出現しない |
| 0x10 | 8 | u8×8 | 敵グループ番号 j：0xFF＝なし |

（ファイルに区域表が無い・短い場合は全 0xFF。）

#### 7.3.4 イベント位置表とイベント領域
- 位置表の要素 i（イベント番号 0〜249）は、イベント領域内のイベント記録のオフセット。0xFFFF＝イベントなし。
- イベント領域は「u16LE 長さ＋データ」の連なり。各イベントは〔長さ 0x62 ＋ イベント記録 0x62 バイト〕〔長さ L0 ＋ ページ 0 のスクリプト〕〔長さ L1 ＋ ページ 1 のスクリプト〕〔L2 ＋ページ 2〕〔L3 ＋ページ 3〕の順。位置表はイベント記録本体（長さの直後）を指し、ページのスクリプト位置はスクリプト本体（長さの直後）を指す。空のスクリプトは長さ 1、内容 0x00 の 1 バイト。
- メモリ上のイベント領域は 32000 バイト。ファイルの S が大きい場合は 32000 で打ち切る。
- スクリプトの命令形式は 22 を参照（各命令は〔命令コード u8、引数長 u8、入れ子の深さ i8、引数…〕、0x00 で終了）。スクリプト実行時の長さはスクリプト位置の直前 2 バイトから得る。

## 8. 画像・チップセット

### 8.1 ECD 形式（MCPnnn.ECD / CHRnnn.ECD）
| オフセット | サイズ | 内容 |
|---|---|---|
| 0 | 48 | パレット：16 色 × (R, G, B)。各バイトの **下位 4 ビット**が 0〜15 の値（上位 4 ビットは無視。実データは常に 0） |
| 48 | 640 × 個数 | パターン（32×32 ドット）の並び |

パターン 640 バイトの内訳：マスク 128、プレーン 0 128、プレーン 1 128、プレーン 2 128、プレーン 3 128。各 128 バイトは 32 行 × 4 バイト、各バイトの最上位ビットが左端。画素の色番号 ＝ プレーン0 | プレーン1<<1 | プレーン2<<2 | プレーン3<<3（プレーン 0〜3 は青・赤・緑・輝度）。
マスクのビット 1＝不透明。スプライトとして重ねる場合、各プレーンについて「下地 AND NOT マスク」OR「パターンのプレーン」を結果とする（マスク 0 の位置でもプレーンのビットが立っていれば下地に OR される）。チップ（地形）として描く場合はマスクを無視して 4 プレーンをそのまま写す。

- MCPnnn.ECD：102448 バイト＝48＋160×640。パターン 0〜159 がチップ番号 0〜159。**このパレットがマップのベースパレット**になる（→ 21）。
- CHRnnn.ECD：41008 バイト＝48＋64×640。パターン 0〜63。論理的には横 8 × 縦 8 の並び（番号＝行×8＋列）。パレットはフィールドでは無視する。
- キャラクタ 1 体は横 2 × 縦 4 のブロック：開始パターン p から、行 r（0＝上向き、1＝右向き、2＝下向き、3＝左向き）・列 c（0, 1＝足踏みの 2 コマ）のパターン p + 8r + c。
- ファイルが無い・短い場合、足りないパターンは全 0（透明・黒）。ECD が 48 バイト未満ならパレットも変更しない。

### 8.2 MCPnnn.DAT（チップ属性表）
1024 バイト：

| オフセット | サイズ | 型 | 意味 |
|---|---|---|---|
| 0x000 | 256 | u8×256 | チップ属性（§8.2.1） |
| 0x100 | 256 | u8×256 | エンカウント種別：0＝出ない、1＝通常、2＝率½、3＝率⅓ |
| 0x200 | 512 | u16LE×256 | 戦闘背景番号（`EBD_BKG/BKGnnn.EBD`） |

読込時の加工（この順）：
1. ファイルが 1024 バイト未満（無い場合を含む）なら、属性を全 0x20、エンカウント種別を全 1、戦闘背景を全 0 とする。
2. 全チップの属性のビット 7 を消す（ファイル中のビット 7 は無視）。
3. チップ 0〜3 の属性にビット 7 を立てる。
4. チップ 0xC0〜0xFF の属性・エンカウント種別・戦闘背景をチップ 0 の値で上書きする。
（チップ 160〜255 のファイル中の値は 0xC0〜0xFF 以外は使われない。実データには残骸が入っている。）

#### 8.2.1 属性ビット
| ビット | マスク | 意味 |
|---|---|---|
| 0 | 0x01 | 下辺が通れない（このチップから下へ出られない／下から入れない…下記） |
| 1 | 0x02 | 左辺が通れない |
| 2 | 0x04 | 右辺が通れない |
| 3 | 0x08 | 上辺が通れない |
| 4 | 0x10 | 覆いかぶさる（飛空艇以外ではこのセルにキャラクタ・イベントを描かない。屋根・木の上など）。飛空艇の着陸不可 |
| 5〜6 | 0x60 | 層属性（§8.2.2） |
| 7 | 0x80 | 船で通行可（チップ 0〜3 とオートタイルだけ。§8.2 手順 3・4） |

辺のビットの判定：方向 d へ「現在のチップ A」から「隣のチップ B」へ動くとき、A の d 側の辺ビット、または B の d の反対側の辺ビットが立っていれば通れない（下へ: A の 0x01 か B の 0x08、左へ: A の 0x02 か B の 0x04、右へ: A の 0x04 か B の 0x02、上へ: A の 0x08 か B の 0x01）。0x0F は全方向通行不可。

#### 8.2.2 層属性（ビット 5〜6）
| 値 | 呼び方（本仕様） | 意味 |
|---|---|---|
| 0x00 | 上層 | 層 0x00 のキャラクタだけが乗れる（橋の上へ続く道など） |
| 0x20 | 下層（標準） | 層 0x20 のキャラクタだけが乗れる。**実データのチップの大半はこれ**（属性ファイルが無いときの既定値もこれ） |
| 0x40 | 橋 | どちらの層からも乗れ、乗っても層は変わらない。層 0x20 のもの（下をくぐるもの）はこのセルでは描かれない |
| 0x60 | 連結（階段） | どちらの層とも行き来でき、主人公の層は 0x60（両方扱い）になる |

（実データ集計: 0x20 が 93%、0x00 が 7%、0x40・0x60 は各 0.5%。）移動・描画での扱いは 21。

### 8.3 EGD 形式（ENSnnn.EGD / ENLnnn.EGD）
| オフセット | サイズ | 内容 |
|---|---|---|
| 0x00 | 48 | パレット（4 ビット値、下位 4 ビット） |
| 0x30 | 1 | サイズ：0＝S（80×96）、1＝L（160×128） |
| 0x31 | 1 | 未使用（0） |
| 0x32 | 5 × W/8 × H | マスク、プレーン 0、1、2、3 の順に、各 H 行 × (W/8) バイト |

S は 4850 バイト（W=80, H=96）、L は 12850 バイト（W=160, H=128）。表示サイズは敵データではなく 0x30 で決まる。50 バイト未満のファイルは画像なし。50 バイト以上で規定サイズに足りないファイルは、パレットとサイズを採用し、マスク・各プレーンの足りない部分を 0 として扱う（各 5 領域を 0 で初期化してから、ファイルにある分だけ写す）。（v1.1 で追記）**読み込んだ敵画像のパレットが戦闘画面のパレットになる**（複数体なら最後に読んだもの → 24）。合成規則は §8.1 のスプライトと同じ（マスク 1 の位置の下地を消して OR）。

### 8.4 全画面画像（TITLE.DAT / PCTnnn.EBD）
128048 バイト ＝ パレット 48 バイト ＋ 4 プレーン × 32000 バイト。
- パレットは **8 ビット値**（各バイトの上位 4 ビットが 0〜15 の色値。実データの TITLE.DAT は上位と下位が同じ値、PCT には異なるものもある。上位 4 ビットだけを使う）。
- 各プレーンは 640×400、1 行 80 バイト、最上位ビットが左。プレーン順は 青・赤・緑・輝度（色番号のビット 0〜3）。
- 128048 バイト未満のファイルは「画像なし」（TITLE.DAT ならタイトル画像なし、PCT なら黒画面のまま、パレットも変えない）。

### 8.5 戦闘背景（BKGnnn.EBD）
41008 バイト ＝ パレット 48 バイト（4 ビット値、下位 4 ビット）＋ 4 プレーン × 0x2800 バイト（640×128、1 行 80 バイト）。画面の Y=104〜231 に描く（→ 24）。41008 バイト未満のファイル（無い場合を含む）は「画像なし」：何も描かず、パレットも変えない（その範囲は直前の画面内容＝戦闘開始演出で塗った色 14 のまま。足りない分を 0 として描くのではない）。（v1.1 で追記）

### 8.6 その他
- `DAT_BGM/*.MML`：テキスト（→ 02）。
- `SOUND.DAT`：効果音定義（→ 02）。効果音番号はゲーム内の番号 n に対しドライバの n+10 番を鳴らす規約（→ 02・21）。

## 9. セーブファイル

### 9.1 ファイル名・スロット
- スロット 4 個（表示名「データ１」〜「データ４」→ 23）。スロット k（0〜3）のファイルはゲームルートの `SAVE(k+1).DAT`（`SAVE1.DAT`〜`SAVE4.DAT`）。
- 書き込みは大文字の名前で新規作成（上書き）。読み込みは大文字小文字を区別せずに探す（実データ `save1.dat`）。
- ファイルが無い（または空）ならロード失敗（何もしない → 23）。

### 9.2 レイアウト（合計 8112 バイト＝0x1FB0）

| オフセット | サイズ | 内容 |
|---|---|---|
| 0x0000 | 0x50 × 12 | パーティ記録 0〜11 の先頭 0x50 バイト（§2.1 の 0x00〜0x4F） |
| 0x03C0 | 0x2A8 | 状態ブロック（§2.2 そのまま） |
| 0x0668 | 0x208 | 所持品：260 組 ×（アイテム番号 u8, 個数 u8） |
| 0x0870 | 1000 | スイッチ 0〜999（各 u8、0/1） |
| 0x0C58 | 200 | 変数 0〜99（各 i16LE） |
| 0x0D20 | 2 | u16LE セーブ時の現在マップのマップ版数（§7.3） |
| 0x0D22 | 250 | 予備領域。**ロード時は読み飛ばす**。参照実装はイベント位置表の先頭 250 バイト（要素 0〜124）を書くが、原本のセーブ実例（05yakata）では全 0 だった。クリーン実装は 0 を書くことを推奨 |
| 0x0E1C | 18 × 250 | イベント 0〜249 の状態部（イベント記録の先頭 0x12 バイト、§7.3.5）。現在マップに存在しないイベントは 18 バイトの 0 |

所持品の詳細：
- 有効な組は先頭から詰めて並ぶ（個数 0 の組で終わる）。追加・削除は先頭 256 組の範囲で行い、詰め直しは 260 組全体で行う。詰め直し後の空き組は（0xFF, 0）。ニューゲーム時は 260 組すべて (0, 0)。
- 個数は 1〜99。

スイッチ：メモリ上は 0〜1000 の 1001 個あるが、保存されるのは 0〜999。スイッチ 1000 はロードしても変化しない（ニューゲームで 0）。

### 9.3 ロード時の適用手順
1. 画面をブラックアウト（速度 1 → 21 §2.2）。
2. パーティ記録の先頭 0x50 バイト ×12、状態ブロック、所持品、スイッチ 1000 個、変数 100 個、マップ版数を順に読み込む（ファイルが途中で終わった場合、末尾で切れた領域とそれ以降の領域は変更しない。領域の単位は「パーティ記録 1 件分 0x50」「状態ブロック」「所持品」「スイッチ」「変数」「版数」「イベント 1 件分 18 バイト」。版数が読めなかった場合は 0 として手順 7 の比較に使う）。予備領域 250 バイトは読み飛ばす。
3. 読込済みマップ番号 ← 現在マップ番号。
4. 現在マップのグリッド・グラフィック・イベントを読み込む（21 §4.1 の手順 1〜3。イベントは初期状態、移動タイマの乱数もここで消費される。CHR スロット・チップセットは読込済み番号が同じなら読み直さない）。
5. 色調を即時に再適用する（状態ブロックの色調値−1 で色調変更、表示更新なし → 21 §2.4）。
6. 主人公・乗り物のスプライトを読み直す。
7. **保存されたマップ版数が、いま読み込んだマップファイルの版数と等しい場合だけ**、イベント状態部を復元する：イベント番号 i ごとに、現在マップにイベント i が存在すれば 18 バイトをその記録の先頭へ上書きし、「現在ページ＋1」が 9（完全消去）でなければ 0（未確定）にする。存在しなければ読み飛ばす。版数が違えば（マップがエディタで更新されていれば）イベントは全部マップファイルの初期状態のまま。
8. 全員の派生値を再計算（§2.3）。
9. マップ進入処理（21 §4.2。マップは読込済みなので再読込はしない。ページ更新・表示位置・層の決定を行う）。
10. 毒フラグを再計算。
11. 現在の BGM を再生。

### 9.4 セーブ時
§9.2 の順にそのまま書く。保存はフィールドメニュー（→ 23）からのみ行われるため、イベント実行中フラグ等の実行時用フィールドは通常 0 のはず。

## 10. RPG.EXE のビルド判別とビルド差分

### 10.1 判別手順
D2 の RPG.EXE には少なくとも 4 つのビルドがあり、いくつかの規則が異なる。ゲームに同梱された RPG.EXE（**実行しない**。バイト列として読むだけ）から次の手順で判別する。

1. ゲームルートの `RPG.EXE` を読む。存在しない、または 0x40 バイト以下なら「1997-10 版」とする。
2. ヘッダ段落数 H ＝ u16LE @0x08。ヘッダサイズ ＝ H × 16。
3. 初期 CS ＝ u16LE @0x16、初期 IP ＝ u16LE @0x14。
4. エントリ位置 E ＝ ヘッダサイズ ＋ CS × 16 ＋ IP。
5. E+3 がファイル長を超える、または E のバイトが 0xBA（16 ビット即値を DX に入れる命令）でなければ「1997-10 版」。
6. 即値 V ＝ u16LE @E+1（データセグメントの段落値）で判別：

| V | ビルド | 本仕様での略称 |
|---|---|---|
| 0x17E1 | 1996-06 版 | 96/06 |
| 0x17E2 | 1996-08 版 | 96/08 |
| 0x17EC | 1997-03 版 | 97/03 |
| その他（実データは 0x17ED） | 1997-10 版（最終版） | 97/10 |

参考：サンプルではエントリ位置は全て 0x2000、エントリのバイト列は `BA xx 17 2E 89 16 FA 01`。ファイルサイズは 96/06＝110607、96/08＝110623、97/03＝110783、97/10＝110799 バイト（判別には使わない）。

### 10.2 サンプルゲームのビルド

|---|---|

### 10.3 ビルド差分一覧
以下の A〜I は本仕様での通し記号（参照実装の文書の記号 A〜H との対応は不明。参照実装のソース注記では「1996 年版の差分」が 5 項目、「97/03 にもある差分」が 1 項目とされている）。「旧版」＝ 96/06 と 96/08 の 2 つ。

| 記号 | 該当ビルド | 内容 |
|---|---|---|
| A | 旧版 | **イベント消去時の地図からの除去**：消去するイベントが下層用の位置図と上層用の位置図の両方に登録されている場合（連結チップ上にいるイベント）、新版は両方から消すが、旧版は下層用だけ消して上層用の登録を残す（→ 21 §7.5、位置図は 21 §5.6）。残った登録は出現条件を満たす限り描画・通行判定に現れ続ける |
| B | 旧版 | **NPC の海チップ規則**：NPC の移動判定で「いまいるチップが 0〜3 またはオートタイル（0xA0 以上）なら、移動先もチップ 0〜3 または 0xA0 以上でなければ動けない（この場合は辺ビットを見ない）」という規則を、旧版は常に適用し、新版は「チップ 0 の属性の下位 4 ビットが 0x0F（全方向通行不可）」のときだけ適用する。適用しない場合は通常の辺ビット判定（→ 21 §8.4） |
| C | 旧版 | **ランダム移動の失敗時の向き**：ランダム移動 NPC が移動に失敗したとき、新版は向きを試行前の向きに戻し、旧版は試行した方向を向いたままにする |
| D | 旧版 | **レベルアップ時の魔法習得**：習得レベルに達したスロット i について、旧版は「習得済み魔法スロット i ← 魔法リストのスロット i」と直接書く。新版は「その魔法番号を魔法リストの先頭から探し、最初に一致したスロットに習得済みとして書く」（同じ魔法が複数スロットにある場合に差が出る） |
| E | 旧版 | **全回復の HP 量**：イベント「全回復」・宿屋の回復で、HP 加算量が旧版 999、新版 9999（いずれも最大 HP で頭打ち。加算は F の規則に従う。ただし全回復は加算の前に HP がちょうど 0 のメンバーを HP 1・生存にするので、F の差が出るのは HP が負のメンバーだけ → 23） |
| F | 96/06・96/08・97/03 | **HP 加算と戦闘不能者**：イベントによる HP 加算（および全回復の HP 加算部分）で、97/10 版は現在 HP が 0 以下のメンバーには加算しない。それ以前の 3 版は戦闘不能者にも加算する（生存フラグは変えない） |
| G | 96/06 のみ | **アイテム所持判定と装備品**：「アイテムを持っているか」の判定（ページ出現条件・条件分岐）で、96/06 版は所持品だけを調べ、装備中の品は数えない。他の版は所持品になければパーティメンバーの装備も調べる |
| H | 96/06 のみ | **ニューゲーム時の変数初期化**：96/06 版は変数 0〜49 だけを 0 にする（50〜99 は直前の値＝前のプレイの値が残る。起動直後は 0）。他の版は 100 個とも 0 にする |
| I | 96/06 のみ | **イベント移動完了待ち**：イベントの移動完了を待つ処理（「イベントを動かす」命令の前の待ち → 22）で、96/06 版は移動の進みが 0 になるまで待ち、他の版は進みが 0 または 32（最終コマ）になった時点で待ちを終える |

（上記以外に、参照実装のソース中でビルドにより分岐する箇所はない。）

## 受け入れテスト観点
1. ビルド判別：§10.2 の全ゲームで表どおりの結果になること（特に brtsky＝96/08、zyuken＝96/06、ring・ygk＝97/03）。RPG.EXE を削除したコピーでは 97/10 になること。
