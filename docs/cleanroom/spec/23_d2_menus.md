## 1. 共通ゲームルール

### 1.1 主人公レコード（実行時）

主人公は 12 人（番号 0〜11）。各主人公は PLAYER.DAT の 200 バイトレコード（20 章）をそのまま実行時データとして持ち、+0x00〜+0x4F がセーブされる。本章で使う欄:

| オフセット | 型 | 意味 |
|---|---|---|
| +0x00 | u8 | レベル |
| +0x01 | u8 | 生存フラグ（0 = 戦闘不能） |
| +0x02 | u8×6 | 状態: 毒, 暗闇, 沈黙, 混乱, 睡眠, 麻痺（各 0/1） |
| +0x08 | u32 | 経験値 |
| +0x0C | u32 | 次のレベルの必要経験値（最大レベルなら 0） |
| +0x10 | i16 | HP |
| +0x12 | i16 | 最大 HP |
| +0x14 | i16 | MP |
| +0x16 | i16 | 最大 MP |
| +0x18 | i16×4 | 素のステータス: 攻撃力, 防御力, 精神力, 素早さ |
| +0x20 | i16×4 | 装備込みステータス（同順） |
| +0x28 | u8×5 | 装備: 0 武器, 1 鎧, 2 盾, 3 兜, 4 装飾品（0xFF = なし） |
| +0x2D | u8×30 | 習得欄（0xFF = 未習得。値は魔法番号） |
| +0x4B | u16 | 歩行グラフィックの CHR ファイル番号 |
| +0x4D | u8 | 歩行グラフィックの位置 |
| +0x50 | 文字列 20 | 名前（NUL 終端） |
| +0x64 | u8 | 最大レベル |
| +0x65 | u8 | 初期レベル |
| +0x66 | u8 | 成長の折れ点レベル K |
| +0x68 | u8×3 | 経験値曲線の係数 A, B, C |
| +0x6B | i16×6 | レベル 1 の値: 最大 HP, 最大 MP, 攻撃力, 防御力, 精神力, 素早さ |
| +0x77 | i16×6 | 10 レベルあたりの成長量（同順） |
| +0x83 | u8×30 | 魔法リストの習得レベル |
| +0xA1 | u8×30 | 魔法リスト（魔法番号。0xFF = なし） |

習得欄 i（0〜29）は魔法リスト i に対応し、習得済みなら魔法リスト i と同じ値、未習得なら 0xFF。

### 1.2 経験値テーブル

レベル L に到達するのに必要な累計経験値 E(L)（すべて整数演算、除算は 0 方向への切り捨て、64 ビット以上の精度で計算）:

1. L < 2 なら E = 0。
2. L > 99 なら L = 99 として計算。
3. a = L + 2。
4. t = ((a×a + 23) × (a × (a − 4))) ÷ 111 + 1。
5. f = (B − 10) × a + (A + 5) × 100（A, B は係数。0〜255 の符号なし値）。
6. E = t × f ÷ 100 + C。

B < 10 のとき f が負になりうる（その場合 E は負または小さくなる）。経験値欄（u32）に代入するときは下位 32 ビットを使う。

- レベルアップ判定・レベルダウン判定（§1.6・§1.7）で経験値と E を比べるときは、両方を **64 ビット符号なし**として比べる。E が負なら非常に大きな値とみなされるので、そのレベルへは上がらず、レベルダウン判定ではそのレベルから下がる（E(1) = 0 なのでレベル 1 で止まる）。
- 全 21 本の D2 サンプルの PLAYER.DAT（252 レコード）で、「次の必要経験値」欄 = E(レベル + 1)（最大レベルなら 0）、最大 HP 欄 = §1.3 の値であることを確認済み。

### 1.3 レベル別ステータス

ステータス項目 j（最大 HP, 最大 MP, 攻撃力, 防御力, 精神力, 素早さ）のレベル L での値。b = レベル 1 の値, g = 成長量, K = 折れ点レベル:

- K < L のとき: 値 = b + (g × (K − 1) を 16 ビット符号付きに切り詰めた値) ÷ 10 + g × (L − K) ÷ 20
- それ以外: 値 = b + g × (L − 1) ÷ 10
- 上限: 最大 HP は 9999、それ以外は 999。上限を超えたら上限にする。下限のクランプはない。
- 結果は 16 ビット符号付きに切り詰める。
- 除算は各項ごとに 0 方向へ切り捨て。

（K を超えたレベルでは成長が半分になる。）

### 1.4 レベル依存値の再計算

1. レベル ≥ 最大レベルなら、レベル := 最大レベル。
2. 最大 HP・最大 MP・素のステータス 4 種を §1.3 で現在レベルから計算する。
3. 次の必要経験値 := レベル = 最大レベルなら 0、そうでなければ E(レベル + 1)。
4. 現在の HP・MP は変えない（クランプもしない）。

### 1.5 ステータス再計算（装備込み）

1. §1.4。
2. 装備込みステータス := 素のステータス。
3. 装備 5 部位それぞれが 0xFF でなければ、そのアイテムの補正値（ITEM.DAT +0x1A, +0x1C, +0x1E, +0x20 の i16: 攻撃力, 防御力, 精神力, 素早さ）を加える。
4. 各値を 0〜999 にクランプ。
5. 習得欄の整合: 習得欄 i が魔法リスト i と異なるなら、習得欄 i := 0xFF。

新規ゲーム開始時・ロード時には 12 人全員に行う。

### 1.6 レベルアップ判定

1. レベル ≠ 最大レベル かつ 経験値 ≥ E(レベル + 1) の間、次を繰り返す:
   1. レベルを 1 上げる。
   2. 魔法リストの習得レベルが新しいレベルと等しい各 i について魔法を覚える:
      - **標準版・1997-03 版**: §1.13 の「魔法の習得」を魔法リスト i の魔法番号で行う（＝リスト中で最初にその番号が現れる欄に習得）。
      - **旧版（1996-06 版・1996-08 版）**: 習得欄 i := 魔法リスト i（その欄に直接）。
      - 両者が異なるのは魔法リストに同じ魔法が重複している場合だけ。
2. §1.5 のステータス再計算。
3. レベルが上がったかどうかを返す（メッセージ表示は呼び出し側。戦闘の表示は 24 章。イベントでは表示しない）。

レベルアップで HP・MP は回復しない（最大値だけ上がる）。

### 1.7 レベルダウン判定

1. レベル > 0 かつ 経験値 < E(レベル) の間、レベルを 1 下げる（E(1) = 0 なので通常は 1 で止まる）。
2. §1.5 のステータス再計算。
3. HP > 最大 HP なら HP := 最大 HP。MP > 最大 MP なら MP := 最大 MP。

### 1.8 HP の加算（イベント・全回復が使う）

主人公の HP に n を加える。
- **標準版**: HP ≤ 0 の主人公には何もしない。
- **旧版・1997-03 版**: HP ≤ 0 でも加算する（生存フラグは変えない）。
- HP := min(HP + n, 最大 HP)。

### 1.9 全回復

1. HP = 0 なら HP := 1、生存フラグ := 1。
2. 麻痺（状態 5）と毒（状態 0）を 0 にする。暗闇・沈黙・混乱・睡眠は変えない。
3. HP の加算（§1.8）を n = 9999（**旧版は 999**）で行う。
4. MP := min(MP + 999, 最大 MP)。

### 1.10 戦闘不能（死亡）

- 生存フラグ 0 が戦闘不能。イベントの「戦闘不能にする」は HP 0・生存 0・状態全消去（22 章）。戦闘での戦闘不能は 24 章。
- 毒の歩行ダメージやイベントの HP 減少では戦闘不能にならない（HP は最低 1）。

### 1.11 ゲームオーバー判定

パーティが 1 人以上いて、かつ「生存フラグ ≠ 0 で麻痺でない」メンバーが 1 人もいないとき真。パーティ 0 人なら偽。

判定する場面: イベントの各コマンドの前（22 章）、戦闘（24 章）。フィールドの通常歩行中には判定しない。

### 1.12 パーティ

- パーティは最大 5 人。状態ブロックにパーティ人数と並び（主人公番号×5）を持つ。並びの先頭が「先頭の主人公」で、フィールドの主人公の絵はその主人公の歩行グラフィック（先頭の番号が 12 以上なら主人公 0 の絵）。
- **加入**: 人数が 5 以上なら何もしない。既にいれば何もしない。そうでなければ末尾に追加。
- **離脱**: いれば取り除き、後ろを詰める。いなければ何もしない。最後の 1 人も外せる（人数 0 もありうる）。
- 加入・離脱・並べ替えの後、先頭の主人公の歩行グラフィックを読み直す（21 章）。HP 等は変えない。

### 1.13 魔法の習得・忘却

- **習得(主人公, 魔法 m)**: 魔法リストを先頭から見て、最初に m と等しい欄 i の習得欄 i := m。リストに m がなければ何もしない。
- **忘却(主人公, 魔法 m)**: 習得欄で m と等しいものをすべて 0xFF にする。

### 1.14 所持品

- 所持品は 260 枠 × 2 バイト（アイテム番号, 個数）。個数 0 の枠は空。常に「詰め」られており、使用中の枠は先頭から連続する。新規ゲームでは全バイト 0。
- 同じアイテムは 1 枠にまとめる。1 枠の上限 99 個。追加・検索で見るのは先頭 256 枠だけ（実質 256 種類まで）。
- **追加(a)**: a = 0xFF なら失敗。先頭 256 枠を順に見て、
  - 空の枠に着いたら、そこに (a, 1) を置いて成功。
  - a の枠に着いたら、個数が 99 なら失敗、そうでなければ +1 して成功。
  - 256 枠すべて別のアイテムで埋まっていれば失敗。
- **詰め**: 260 枠のうち個数 ≠ 0 の枠を順序を保って前に詰め、残りを (0xFF, 0) にする。
- **削除(a)**（1 個減らす）:
  1. 先頭 256 枠で個数 ≠ 0 かつ番号 a の枠があれば、個数を 1 減らし、0 になったら詰めて成功。
  2. なければ、パーティの並び順に各メンバーの装備 5 部位（部位順）を見て、a（≠ 0xFF）を装備している最初の部位を 0xFF にし、そのメンバーのステータス再計算をして成功（装備品は消える）。
  3. どちらでもなければ失敗。
- **整理（末尾へ移動）(a)**: a の枠を見つけたら、その個数を覚えて枠を空にし、詰め、最初の空き枠に (a, 覚えた個数) を置く。
- **捨てる（1 枠まるごと）(a)**: a の枠を空にして詰める。
- **所持判定(a)**: a = 0xFF なら偽。先頭 256 枠に個数 ≠ 0 の a があれば真。なければ、パーティの誰かが a を装備していれば真（**1996-06 版は装備品を見ず、偽**）。イベントの条件・ページ出現条件で使う。

### 1.15 所持金

- u32。上限 999999。
- **増加**: 加えて 999999 を超えたら 999999。
- **減少**: 所持金 < 金額なら 0、そうでなければ減算。
- 所持金ウィンドウ表示時にも 999999 を超えていれば 999999 にする。

### 1.16 毒

- **毒フラグの更新**: パーティの誰か 1 人でも毒（状態 0）なら状態ブロックの毒フラグ := 1、そうでなければ 0。イベントの毒関連コマンド・全回復・メニューを閉じるとき・宿・ロード時に行う。
- **歩行ダメージ**: イベント実行中でなく、徒歩で、毒フラグが 1 のとき、主人公の 1 歩の更新（21 章）で、
  - その更新の開始時点でスクロール量が 24 なら: トーン値 T := 160 にして反映（画面が白っぽく光る）し、パーティの毒のメンバーで HP > 1 の者の HP を 1 減らす。
  - スクロール量が 32 なら: T := 100 にして反映。
  - 普通速度の 1 歩（スクロール量 8→16→24→32）につき 1 回、光るのは 1 tick（3 VSYNC）。高速移動（スクロール量 16→32）では 24 を通らないのでダメージなし。
  - 毒では戦闘不能にならない（HP 1 で止まる）。

## 2. 共通 UI 部品

### 2.1 ウィンドウ枠

位置 (x, y)、大きさ w×h のウィンドウ:

1. x を 8 の倍数に切り下げた位置から、幅 (w ÷ 8 の商) × 8、高さ h を色 0 で塗る。
2. 色 14 の矩形の輪郭（両端含む）: (x, y)〜(x+w−1, y+h−1)。
3. 色 14: (x+1, y+1)〜(x+w−2, y+h−2)。
4. 色 15: (x+2, y+1)〜(x+w−3, y+h−2)。
5. 色 15: (x+1, y+2)〜(x+w−2, y+h−3)。
6. 色 15: (x+3, y+3)〜(x+w−4, y+h−4)。

（結果として外周 1 ドットが色 14、その内側が白の太枠になる。色番号はパレット番号なので、実際の色はその時のパレット＝通常はマップのチップセットのパレット。）

文字はすべて色 15 で描き、消すときは色 0 で同じ文字を描くか色 0 で塗る（22 章 §6.2 の字形描画）。

### 2.2 選択カーソル

22 章 §6.4 の汎用選択（カーソル外字 SJIS 0xEB9F、位置 (x+16, y+16+24×位置)、31 フレーム周期の点滅、↑↓で回り込み、←→は効果音 1 のみ、決定=効果音 2、取消=効果音 3）。以下「選択(x, y, 項目数, 初期位置, 取消モード)」と書く。取消モード 1 は取消キーで −1、0 は取消キー無効、2 は取消キーで −1（1 と同じ）に加えて決定時にカーソルを消す。

### 2.3 2 列リストウィンドウ

所持品・装備候補・魔法・ワープ先の一覧に使う。種類ごとの違いは下表。

| 項目 | 所持品 | 装備候補 | 魔法 | ワープ先 |
|---|---|---|---|---|
| 列の間隔 | 0xC0 | 0xC0 | 0xC0 | 0xA0 |
| ウィンドウ幅 | 0x1A0 | 0x1A0 | 0x1A0 | 0x160 |
| 1 欄の消去幅 | 0x16×8 | 0x16×8 | 0x16×8 | 0x12×8 |
| 欄の内容 | 名前 + 「：%2d」個数 | 名前 + 「：%2d」個数 | 名前 + 「[%2d]」消費 MP | MAPNAME.DAT のマップ名（16 バイト。マップ番号 mod 1000） |
| 「空」の判定 | 個数 0 | 個数 0 | 魔法番号 0xFF | マップ番号 0xFFFF |
| ページ・カーソルの記憶 | 共有（所持品用 1 組） | 記憶しない（毎回 0） | 主人公ごとに 1 組 | ワープ用 1 組（どこでも初期化されず、タイトルに戻ってもプログラム終了まで残る） |
| 右矢印の x | x+400 | x+400 | x+400 | x+0x150 |

**内容の並び**:
- 所持品: 所持品 260 枠そのまま。
- 装備候補（主人公 c・部位 s）: 所持品の先頭から、空でない枠のうち「アイテムの種類 = s+1」かつ「装備可能ビット（ITEM.DAT +0x17 の u16）のビット c が 1」のものを順に詰めて並べる。残りは空（候補一覧は 260 欄）。
- 魔法（主人公 c）: 習得欄 30 個のうち 0xFF でないものを順に詰めて並べる（後ろは空）。
- ワープ先: 登録済みワープ地点を登録順（後ろは空）。正確には、一覧の先頭から「ワープ地点数」（状態ブロックの登録数）個の欄に、ワープ地点 0, 1, … のマップ番号をそのまま入れ、それより後ろの欄は**状態ブロックの中身に関係なく**空（0xFFFF）とする。登録数より前の欄でもマップ番号が 0xFFFF なら空として扱う（表示しない・決定できない・「続きあり」の判定でも空）。登録数が 30 を超える値（データ破損）は 参照実装では範囲外参照で未定義。クリーン実装は 30 として扱うことを推奨。（v1.1 で追記）

**表示**（ページ番号 P = 左列の列番号）:
0. 開始時に**キーバッファを空にし**、VSYNC を 1 回待ち、点滅カウンタを 0 にする。これはフィールド（所持品・装備候補・魔法・ワープ先）でも戦闘（24 章 §8.2 の魔法・アイテム一覧）でも同じ（同一の処理）。（v1.1 で追記）
1. ウィンドウ (x, y) 大きさ 幅×0x90 を描く（最初に 1 回だけ）。
2. 列 c = 0, 1、行 r = 0〜4 の欄は、一覧の (P + c)×5 + r 番目。文字の左端 nx = x + c×列間隔 + 0x28、上端 ny = y + 24r + 16。まず (nx ÷ 8 の商 − 2)×8 から消去幅 × 16 を色 0 で塗り、空でなければ名前を (nx, ny)、個数/消費 MP を (nx + 0x80, ny) に描く。ページを描く前に VSYNC を 1 回待つ。
3. 左矢印（外字 SJIS 0xEBB4）を (x+8, y+0x78) に、P > 0 なら色 15、そうでなければ色 0（消す）。
4. 右矢印（外字 SJIS 0xEBB5）を (右矢印の x, y+0x78) に、「続きあり」なら色 15、そうでなければ色 0。
   - 続きあり: 所持品・魔法・ワープ先は「一覧の (P+2)×5 番目が空でない」。装備候補は「(P+2)×5 − 1 番目（右列の最下段）が空でない」（右列が埋まっていれば、次の列が空でも矢印が出てめくれる）。
5. カーソル位置（0〜9。0〜4 が左列、5〜9 が右列）: (x + (位置 ÷ 5 の商)×列間隔 + 0x18, y + (位置 mod 5)×24 + 16)。点滅は §2.2 と同じ（t < 4 で描き、21〜23 で消し、t > 30 で 0）。

**キー操作**（1 フレームごとに STOP 検査とキーバッファ 1 個の取り出し）:

| キー | 動作 |
|---|---|
| 取消 | 効果音 3。（装備候補ならカーソルを消す。所持品・魔法・ワープ先ではカーソルを消さず、点滅のその時点の状態のまま残す。v1.1 で追記）−1 を返す |
| 決定 | 効果音 2。装備候補: カーソルを消し、§6.3 の装備変更を行って終了（空欄でも決定できる＝外す）。その他: 選んだ欄が空でなければカーソルを色 15 で描いて、アイテム番号（所持品）/ 魔法番号 / ワープ地点の通し番号（P×5 + 位置）を返す。空欄なら何もしない（効果音 2 だけ鳴る） |
| ↑ | 効果音 1。位置 −1。0 の上は 4、5 の上は 9（列内で回り込み） |
| ↓ | 効果音 1。位置 +1。4 の下は 0、9 の下は 5 |
| → | 効果音 1。左列なら位置 +5。右列なら、続きありのとき P+1（1 列ぶんスクロール。カーソルは右列の同じ行のまま）、なければ何もしない |
| ← | 効果音 1。右列なら位置 −5。左列なら、P > 0 のとき P−1、なければ何もしない |

- 位置または P が変わったら、P が変わった場合はページ全体を描き直し、位置だけなら前のカーソルを消す。動いたときは点滅カウンタを 0 に戻す（すぐ表示）。
- 装備候補では、ページか位置が変わるたび（最初も）に**能力値の変化予告**を表示する: その主人公のコピーで対象部位をカーソル位置の欄のアイテム（空なら 0xFF＝外す）に替え、素のステータス + 全装備補正を 0〜999 にクランプした値から、現在の装備込みステータスを引いた差を、(0x128, 0x60 + 24i)（i = 攻撃力, 防御力, 精神力, 素早さ）に「%+4d」（符号付き 4 桁右詰め。例「  +5」「 -12」「  +0」）で描く。描く前に (0x128, 0x60) から 40×0x58 を色 0 で塗る。

### 2.4 メニュー内メッセージ欄

- **欄を開く**: ウィンドウ (80, 256) 大きさ 480×96。
- **第 n 行に表示**（n = 0, 1）: (104, 272 + 24n) から 432×16 を色 0 で塗り、文字列を (104, 272 + 24n) に色 15 で一括表示（文字送りなし・制御記法なし）。

### 2.5 所持金ウィンドウ

基準位置 (x, y)。単位文字列 U = WORD.DAT 0x6F（NUL 終端）、U のバイト数を u とする。

1. 所持金 > 999999 なら 999999 にする。
2. ずれ o = 0x30 − 8u。
3. ウィンドウ (x + o, y) 大きさ (0x88 − o)×0x30。
4. 文字列「所持金を 10 進 6 桁右詰め（空白埋め）」+ U を (x + o + 0x18, y + 16) に描く。

（U が 1 バイトなら o = 0x28 でウィンドウ幅 0x60。U が 6 バイトを超えると o が負になりウィンドウが左へ広がる。）

使用位置: フィールドメニューでは (0x1C8, 0x120)、店・宿・文章中の `\$` では (0x198, 0x130)。

## 3. フィールドメニュー

### 3.1 開く条件

フィールドのメインループで、主人公が静止中・イベント実行中でない・乗り物が徒歩か船（飛空艇でない）ときに取消キー（ESC）を押すと開く（21 章）。

### 3.2 開く処理と画面構成

1. カーソル記憶を初期化する: メインコマンド位置 0、メンバー選択位置 0、所持品リストのページ・位置 0、全主人公の魔法リストのページ・位置 0。（記憶はメニューを開いている間だけ有効で、閉じて開き直すと消える。）
2. **メニュー画面の描画**:
   1. VSYNC 1 回、T = 0 を反映（暗転）。
   2. グラフィック画面全体を色 14 で塗る。（テキスト層のフィールド用マスクはそのまま残る。）
   3. コマンドウィンドウ（§3.3）を (0x30, 0x30) に。
   4. パーティウィンドウ（§3.4）を (0xC0, 0x30) に。
   5. テストプレイ時のみ: ウィンドウ (0x30, 0x120) 大きさ 352×48 と、(72, 304) に「MAP=%03d:%-18s(X=%03d,Y=%03d)」（マップ番号, 現在マップのヘッダのマップ名 16 バイト, 主人公の X, Y）。
   6. 所持金ウィンドウを (0x1C8, 0x120) に。
   7. VSYNC 1 回、T = 100 を反映。
3. 効果音 2。

### 3.3 コマンドウィンドウ

- 並べ替え禁止でないとき: ウィンドウ 120×144、項目 5 つ。禁止中: 120×120、項目 4 つ（「並び替え」を除く）。
- 項目は (x+32, y+16+24k):

| k | 文字列 | 出所 |
|---|---|---|
| 0 | アイテム系の名称 | WORD.DAT 0xAF（戦闘コマンドの「持ち物」名と共通） |
| 1 | 魔法系の名称 | WORD.DAT 0xA4（戦闘コマンドの「特技/魔法」名と共通） |
| 2 | 装備 | 内蔵 |
| 3 | 並び替え（禁止中は出さない） | 内蔵 |
| 3 または 4 | システム | 内蔵 |

### 3.4 パーティウィンドウ

- パーティ 0 人なら何も描かない。
- ウィンドウ (x, y) 大きさ 400×(人数×24 + 24)。
- 各メンバー（並び順 k）を (x+32, y+16+24k) に 1 行で:
  1. 名前を (x+32, ·)。
  2. 状態欄を (x+32+0x88, ·): 戦闘不能なら WORD.DAT 0xC5 + 9×6（「気絶」等）。生存なら状態 5,4,3,2,1,0（麻痺, 睡眠, 混乱, 沈黙, 暗闇, 毒）の順に見て最初に立っている状態 s の名前 WORD.DAT 0xC5 + 9s。どれも立っていなければ「Ｌ%2d」（全角 L + レベル 2 桁）。
  3. (x+32+200, ·) に「%4d/%4d%5d/%3d」（HP, 最大 HP, MP, 最大 MP）。

### 3.5 メインループ

1. 選択(0x30, 0x30, 項目数, 記憶位置, 1)。結果を記憶位置にする。
2. 取消なら「メニューを閉じる」（§3.6、フェードなし）で終了。
3. 並べ替え禁止中に位置 3 を選んだらシステムとみなす。
4. 各コマンドを実行（§4〜§8）。
5. ロードに成功していたら（§8）、そのままメニューを終える（閉じる処理はロード側で済み）。
6. **アイテム/魔法の効果でイベント実行中フラグが立っていたら**（ワープ・洞窟脱出・スイッチ型。§9）:
   1. イベント実行中フラグを 0 にする。
   2. 洞窟脱出要求があれば: 要求を下ろし、主人公を洞窟脱出地点（マップ, X, Y）へ、向きを下（2）にし、マップ入場処理（21 章）。直前 BGM := 現在 BGM、現在 BGM := 脱出地点の BGM 名、BGM 再生要求。
   3. ワープ要求があれば: 要求を下ろし、ワープ選択番号 i が 30 未満なら、主人公をワープ地点 i（マップ, X, Y）へ、向きを下にし、マップ入場処理。直前 BGM := 現在 BGM、現在 BGM := その地点の BGM 名、再生要求。
   4. メニューを閉じる（フェードなし）で終了。（スイッチ型の場合は、閉じた後フィールドの自動イベント等がスイッチに反応する。）
   - **スイッチ型の後のキー待ち中の STOP**（v1.1 で追記）：スイッチ型（§9.1 の k = 8 種類 6 / k = 10、§9.2 の種類 6）はイベント実行中フラグを 1 にした後で「キー離し→押し」待ち（22 章 §6.3、STOP 検査あり）を行うので、テストプレイ中にここで STOP（CTRL＋取消）を押すと中断が起きうる。原本ではイベントが実行されていないのにイベント中断の戻り先へ飛ぶことになり**未定義**、参照実装でも中断を受け止める場所がなく異常終了する。クリーン実装の推奨：メニューの中で中断を受け止め、キー待ちが終わったのと同じ扱いにする。すなわちこの手順 6 へ進み（イベント実行中フラグを 0 にし、スイッチ型なので洞窟脱出・ワープ要求は無い）、メニューを閉じる（フェードなし）。スイッチはすでに ON、アイテムはすでに削除済み（消耗品の場合）/ MP は消費済みのまま。通常どおりキーで抜けた場合と最終状態は同じになる。ワープ・洞窟脱出はフラグを立てた直後にキー待ちなしで戻るので STOP の機会は無い。
7. それ以外はメニュー画面を描き直して（§3.2 の 2）1 に戻る。

各サブコマンドから戻ると、常にメニュー画面全体が描き直され、コマンド選択に戻る（アイテムを使った後もアイテム一覧には戻らない）。

### 3.6 メニューを閉じる

引数: フェード速度 f（0 = フェードなし）。
1. 毒フラグの更新。全イベントのページ再評価。
2. VSYNC 1 回、T = 0 を反映。フィールドを全面再描画。VSYNC 1 回。
3. f ≠ 0 なら速度 f のブラックイン、f = 0 なら T = 100 を即反映。
4. キーバッファを空にする。

4. コマンド選択へ戻る。

## 6. 装備とステータス表示

### 6.1 流れ

1. メンバー選択（§5 の 1 と同じ、記憶位置共有）。取消ならコマンド選択へ。
2. 部位位置 s := 0。
3. ステータスウィンドウ（§6.2）を (0x88, 0x18) に描く。

「状態」を見るための独立したコマンドはなく、装備画面のステータスウィンドウが兼ねる。

### 6.3 装備変更

主人公 c、部位 s、選んだ欄のアイテム n（空欄なら 0xFF）:
1. 旧装備 o := 部位 s の装備。
2. 部位 s := n。
3. o を所持品に追加（o = 0xFF なら何もしない。追加に失敗すると o は消える）。
4. n を所持品から 1 個削除（n = 0xFF なら何もしない）。
5. ステータス再計算（§1.5）。

装備変更のメッセージはない。呪いの概念はない。

## 7. 並び替え

1. パーティ人数が 1 以下なら何もしない。
2. 「確定数」k := 0、各メンバー「使用済み」を偽にする。
3. k < 人数 − 1 の間:
   1. 番号表示: (0xC8, 0x40) から 8×(人数×24) を色 0 で塗り、確定済みの j（0〜k−1）について、j+1 を 10 進で (0xC8, 0x40 + 24×(j 番目に選ばれたメンバーの位置)) に描く。
   2. 選択(0xC0, 0x30, 人数, メンバー記憶位置, 2)。
   3. 取消: k = 0 なら並び替えを中止（何も変えない）してコマンド選択へ。そうでなければ k を 1 戻し、最後に選んだメンバーを未使用に戻す。
   4. 決定（位置 i）: メンバー記憶位置 := i。i が未使用なら、新しい並びの k 番目を i のメンバーにし、使用済みにして k を 1 進める。使用済みなら何もしない。
4. 残った最後の 1 人を新しい並びの末尾にする。
5. 全員の番号を表示し、キーバッファから何かキーが 1 つ来るまで待つ（どのキーでもよい。取消でも確定）。この待ちは 01 章 §4.3 の「打鍵があるまで待つ」そのもの：**キーバッファを空にしない**、**STOP 検査をしない**、まずバッファを見て打鍵があれば即座に取り出して終わり、無ければ VSYNC を 1 回待ってまた見る（VSYNC を待ってから見るのではない）。直前の選択の後にバッファに残っていた打鍵があれば、待たずに確定する。（並び替えはイベント実行中には開けないので、STOP 検査の有無は結果に影響しない。）（v1.1 で追記）
6. パーティの並びを新しい並びに置き換え、先頭の主人公の歩行グラフィックを読み直す。

## 8. システム

### 8.1 システムウィンドウ

- 位置 (0x40, 0x88)。テストプレイ時は大きさ 120×120 で項目「セーブ」「ロード」「デバッグ」「終了」、通常時は 104×96 で「セーブ」「ロード」「終了」。項目は (0x60, 0x98+24k)。
- 選択(0x40, 0x88, 項目数, 0, 1)（毎回位置 0 から）。取消ならコマンド選択へ。

### 8.2 スロットウィンドウ

基準 (x, y)、大きさ 120×120、項目「データ１」「データ２」「データ３」「データ４」（全角数字）を (x+32, y+16+24k)。スロット k はファイル `SAVE(k+1).DAT`（ゲームのルートディレクトリ。SAVE1.DAT〜SAVE4.DAT）。

### 8.3 セーブ

1. スロットウィンドウを (0x48, 0xA8) に、選択(0x48, 0xA8, 4, 0, 1)。
2. 決定ならそのスロットに保存（§8.5）。確認・上書き確認・完了メッセージは **ない**。保存の失敗も通知しない。
3. コマンド選択へ戻る（メニューは開いたまま）。

### 8.4 ロード

1. スロットウィンドウを (0x48, 0xC0) に、選択(0x48, 0xC0, 4, 0, 1)。
2. 決定でファイルが存在すれば §8.6 で読み込み、メニューを閉じる（フェード速度 1 のブラックイン）。メニューは終了し、フィールドへ戻る。
3. ファイルが無ければ何も起きずコマンド選択へ戻る（メッセージなし）。

タイトル画面の「コンティニュー」も同じスロットウィンドウ (0x108, 0xD0) と同じ読み込み処理を使う（21 章）。

### 8.4a デバッグ・終了

- **デバッグ**（テストプレイ時のみ）: §10 のデバッグメニュー。戻るとコマンド選択へ（メニュー画面を描き直す）。
- **終了**: 確認なしで、速度 1 のブラックアウトの後、ゲームを終了する（タイトル画面には戻らず、BGM を止めてプログラム終了。イベントコマンド 0x62 と同じ終わり方。22 章）。

### 8.5 保存の内容と順序

ファイル形式（オフセット・サイズ）は 20 章。書き出す順:
1. 主人公 12 人の各レコード先頭 0x50 バイト。
2. 状態ブロック（0x2A8 バイト）。
3. 所持品（0x208 バイト = 260 枠×2）。
4. スイッチ 0〜999（1000 バイト。スイッチ 1000 は保存されない）。
5. 変数 100 個（i16LE、200 バイト）。
6. 現在マップの「マップ識別値」（MAP ファイルのイベント領域にある u16。20 章）。
7. イベント表（参照実装は u16×250 の表の先頭 250 バイト＝125 個分だけを書く。読み込み時は読み飛ばすので実害はない。原本のサイズは【未確認】）。
8. イベント 0〜249 それぞれについて、イベントレコードの先頭 18 バイト（存在しないイベントは 0 埋め 18 バイト）。

### 8.6 読み込みの手順

1. ファイルが無ければ失敗を返す。
2. 速度 1 のブラックアウト。
3. §8.5 の 1〜6 の順に読み込む（主人公レコード先頭 0x50 バイト、状態ブロック、所持品、スイッチ 1000、変数 100、保存時のマップ識別値）。7 は読み飛ばす。
4. 「読込済みマップ」を状態ブロックのマップ番号にし、そのマップのグリッド・イベント・グラフィックを読み込む（21 章）。色調を「設定のみ」で再適用（22 章 §6.8）。主人公・乗り物の歩行グラフィックを読み直す。
5. 保存時のマップ識別値が、今読み込んだ MAP ファイルの識別値と一致する場合だけ、各イベント（存在するもの）のレコード先頭 18 バイトをファイルの値で上書きし、現在ページ+1 が 9（消去済み）でなければ 0（未評価）にする。一致しなければイベントは MAP ファイルの初期状態のまま（マップが編集された場合の保護）。
6. 主人公 12 人のステータス再計算（§1.5）。
7. マップ入場処理（21 章: ページ再評価・表示位置など）。
8. 毒フラグの更新。
9. 現在 BGM を再生要求。
10. 成功を返す。

### 9.1 アイテム使用

アイテム a（種類 k）。**使用者** = パーティ先頭の主人公（番号が 12 以上なら主人公 0）。魔法効果アイテムの威力計算の「術者」に使う。m = a の魔法番号。

1. **対象選択**: k が 6（薬・単体）または 9（魔法書）、または k = 8 で魔法 m の種類が 0（味方単体）なら、対象選択（§9.4）。取消ならコマンド選択へ戻る（アイテムは減らない）。
2. **ワープ先選択**: k = 8 で魔法 m の種類が 4（ワープ）なら、ワープ地点が 0 件ならワープ選択番号 := 0xFF。1 件以上ならワープ先リスト（§2.3）を (0xC0, 0x38) に開き、取消ならコマンド選択へ、決定ならワープ選択番号 := その通し番号。
3. **魔法書（k = 9）**:
   1. メッセージ欄を開く（§2.4）。
   2. 対象の 30 欄を先頭から見て、最初に「習得欄 = m」なら「習得済み」、「魔法リスト = m」なら「習得可能」として打ち切る（同じ欄では習得欄を先に見る）。どちらもなければ「不可」。
   3. 習得済み: 第 0 行に「すでに覚えている。」
   4. 習得可能: 効果音 8、第 0 行に「<対象名>は<魔法名>を覚えた！」、魔法の習得（§1.13）、消耗するならアイテムを 1 個削除。
   5. 不可: 第 0 行に「<対象名>は<アイテム名>を使えない。」
   6. 「キー離し→押し」待ち（22 章 §6.3）の後、コマンド選択へ戻る。
4. 「効果あり」を偽にする。メッセージ欄を開き、第 0 行に「<アイテム名>を使った！」。
5. k = 8 で魔法 m の種類が 2・3（敵向け）以外なら魔法 m のフラッシュ（§9.5）、それ以外は「待ち単位」2 回（SHIFT なしで 14 VSYNC、SHIFT 押下中は 6 VSYNC。1 単位 = 7 VSYNC / SHIFT 時 3 VSYNC）。
6. 種類ごとの効果:
   - **k = 8（魔法効果）**: 魔法 m の種類で
     - 0: 魔法の効果（§9.3）を使用者 → 対象。
     - 1: パーティ全員に順に魔法の効果。
     - 4（ワープ）: ワープ地点が 1 件以上・ワープ禁止でない・徒歩 のすべてを満たせば、速度 2 のブラックアウト、ワープ要求 := 1、イベント実行中フラグ := 1、消耗するならアイテムを削除して **即終了**（キー待ちなし。§3.5 の 6 で移動する）。満たさなければ効果なし（手順 7 の「しかし何も起こらなかった！」になり、アイテムは減らない）。
     - 5（洞窟脱出）: 洞窟脱出禁止でなく徒歩なら、速度 2 のブラックアウト、洞窟脱出要求 := 1、イベント実行中フラグ := 1、消耗するなら削除して即終了。満たさなければ効果なし（同上）。
     - 6（スイッチ）: 効果あり := 真。魔法のスイッチ番号 ≤ 1000 ならそのスイッチを ON。イベント実行中フラグ := 1。
     - 2・3: 何も起きない。
   - **k = 6**: アイテムの効果（§9.3）を対象に。
   - **k = 7**: パーティ全員に順にアイテムの効果。
   - **k = 10（スイッチ）**: 効果あり := 真。スイッチ番号 ≤ 1000 なら ON。イベント実行中フラグ := 1。
   - その他（0〜5）: 何も起きない。
7. 効果ありなら、消耗するアイテムを 1 個削除。効果なしなら第 1 行に「しかし何も起こらなかった！」（アイテムは減らない）。
8. 「キー離し→押し」待ちの後、コマンド選択へ戻る（スイッチ型は §3.5 の 6 でメニューを閉じる）。

### 9.2 魔法使用（フィールド）

術者 c、魔法 m。

1. 種類 0 なら対象選択（§9.4。取消でコマンド選択へ、MP は減らない）。種類 4 なら §9.1 の 2 と同じワープ先選択（0 件なら選択番号 0xFF。取消でコマンド選択へ）。
2. 効果あり := 偽。メッセージ欄を開き、第 0 行に「<術者名><発動メッセージ>」。
3. 魔法のフラッシュ（§9.5）。
4. 術者の MP < 消費 MP なら、第 1 行に「<MP の名称（WORD.DAT 0x0B）>が足りない！」を表示して 7 へ（MP は減らない。フラッシュは既に出ている）。
5. MP −= 消費 MP。種類ごとに:
   - 0: 魔法の効果を術者 → 対象。
   - 1: パーティ全員に順に。
   - 4: ワープ地点 1 件以上・ワープ禁止でない・徒歩なら、速度 2 のブラックアウト、イベント実行中フラグ := 1、ワープ要求 := 1 で **即終了**（キー待ちなし）。
   - 5: 洞窟脱出禁止でなく徒歩なら、速度 2 のブラックアウト、イベント実行中フラグ := 1、洞窟脱出要求 := 1 で即終了。
   - 6: 効果あり := 真、スイッチ番号 ≤ 1000 なら ON、イベント実行中フラグ := 1。
   - それ以外（2・3 の敵向けなど）: 効果あり := 真（何も起きないが失敗表示もしない。MP は消費される）。
6. **失敗表示**:
   1. 効果ありが偽で種類が 4 未満なら、効果ビット 0〜19 が 1 つも立っていない魔法は効果あり := 真とする（効果の無い魔法は失敗扱いにしない）。
   2. なお効果ありが偽で、失敗時メッセージ種別 ≤ 1 なら、第 1 行に WORD.DAT（0x4A0 + (種別 + 9) × 0x1D）の文字列 = 種別 0 なら **0x5A5**、種別 1 なら **0x5C2** を表示する（術者名などは付けない）。種別 2 以上は何も表示しない。
   - ワープ・洞窟脱出が条件不成立のときもここに来る（種類 4・5 なので手順 1 は飛ばし、種別に応じた失敗表示）。
7. 「キー離し→押し」待ちの後、コマンド選択へ戻る。

### 9.3 効果の適用

**威力（術者 c, 魔法 m）**:
1. v = 基本威力。
2. 攻撃力係数 ≠ 0 なら v += (c の装備込み攻撃力 × 係数 を 16 ビット符号付きに切り詰めた値) ÷ 10。
3. 精神力係数 ≠ 0 なら v += (装備込み精神力 × 係数 を 16 ビットに切り詰め) ÷ 10。
4. v ≤ 1 なら v = 1（ばらつきなし。乱数を引かない）。そうでなければ v = ばらつき(v, 魔法のばらつき)。
5. v > 30000 なら 30000。

**ばらつき(v, p)**（戦闘と共通。24 章も同じ式）:
1. p ≤ 0 なら v のまま（乱数を引かない）。
2. 乱数を 1 回引き、v += 乱数 mod 3。
3. r = v × p ÷ 12。
4. r > 1 なら乱数をもう 1 回引き、v += r ÷ 2 − (乱数 mod r)。

**魔法の効果（術者 c → 対象 p, 魔法 m）**:
1. p が生存なら:
   1. ビット 0 が立っていれば HP 回復(p, 威力(c, m))。
   2. s = 0〜5 の順に、ビット s+2 が立っていれば、威力(c, m) を計算してから（**値は使わないが乱数は引かれる**）状態回復(p, s)。
2. ビット 8 が立っていれば、威力(c, m) を計算して蘇生(p, 威力)（p が戦闘不能のときだけ効く）。

**アイテムの効果（対象 p, アイテム a）**:
1. p が生存なら:
   1. 回復ビット 6（蘇生）が立っておらず HP 回復量 ≠ 0 なら HP 回復(p, HP 回復量)。
   2. MP 回復量 ≠ 0 なら MP 回復(p, MP 回復量)。
   3. s = 0〜5 の順に、回復ビット s が立っていれば状態回復(p, s)。
2. 回復ビット 6 が立っていれば蘇生(p, HP 回復量)。

**HP 回復(p, n)**:
1. n := min(n, 9999)。
2. 「効果あり」が既に真なら、待ち単位 4 回（28 VSYNC / SHIFT 時 12 VSYNC）待つ（2 つ目以降のメッセージの前の間）。
3. 効果あり := 真。
4. 第 1 行に、n = 9999 なら「<p の名前>の<HP 名称（WORD.DAT 0x00）>が全回復した！」、そうでなければ「<p の名前>の<HP 名称>が<n>回復した！」。
5. HP := min(HP + n, 最大 HP)。（表示の数値は実際の回復量ではなく n。n が負なら HP が減る。下限処理はない。）

**MP 回復(p, n)**: HP 回復と同様。上限 999、全回復表示は n = 999 のとき、名称は WORD.DAT 0x0B、MP := min(MP + n, 最大 MP)。

**状態回復(p, s)**（s = 0〜5）:
1. p の状態 s が立っていなければ何もしない（メッセージも待ちもない）。
2. 効果ありが既に真なら待ち単位 4 回。効果あり := 真。
3. 状態 s := 0。
4. 第 1 行に「<p の名前>」+ WORD.DAT（0x167 + s × 0x84）（各状態の「治った」文。s=0: 0x167, 1: 0x1EB, 2: 0x26F, 3: 0x2F3, 4: 0x377, 5: 0x3FB）。

**蘇生(p, n)**:
1. p が生存していれば何もしない。
2. 効果ありが既に真なら待ち単位 4 回。効果あり := 真。
3. 生存フラグ := 1、HP := min(n が 0 なら 1 そうでなければ n, 最大 HP)。状態は変えない。
4. 第 1 行に「<p の名前>」+ WORD.DAT（0x167 + 6 × 0x84 = 0x47F）。

メッセージはすべてメッセージ欄の第 1 行に上書きされる（前の行を消してから描く）。

### 9.4 対象選択

パーティウィンドウ（§3.4）を (0xC0, 0x50) に描き（メニューの上に重ねる）、選択(0xC0, 0x50, 人数, 0, 1)（毎回位置 0 から。メンバー記憶位置は使わない）。結果はその位置のメンバーの主人公番号、取消なら −1。

### 9.5 魔法のフラッシュ

1. 魔法の効果音番号で効果音要求。
2. 「フラッシュする」が 0 なら、待ち単位 3 回（21 VSYNC / SHIFT 時 9 VSYNC）待って終わり。
3. 現在のパレットを覚え、次を 10 回繰り返す（計 30 VSYNC）:
   1. 16 色すべてをフラッシュ色（各成分 × 0x11 の 8 ビット値）にする。
   2. VSYNC 2 回待ってからパレット反映（現在のトーン値で。フラッシュ色が 1 フレーム表示される）。
   3. パレットを覚えた値に戻し、VSYNC 1 回待ってから反映。

（「～」は SJIS 0x8160。数字は半角。）

- 選択(0x40, 0x88, 7, 前回位置, 1)。位置はデバッグメニュー内で記憶。（範囲の明確化。v1.1 で追記：記憶はデバッグメニューを 1 回開いている間だけ。システムの「デバッグ」から入るたびに位置 0 から始まり、ビューア・変数エディタから戻ったときや敵出現の切替えの後は直前に選んだ位置に戻る。取消でデバッグメニューを出ると記憶は捨てられる。）取消でシステムを経てコマンド選択へ戻る（メニュー画面を描き直す）。

### 10.2 スイッチビューア（ページ q = 0〜4、スイッチ 200q〜200q+199）

- グラフィックにウィンドウ (144, 0) 大きさ 352×383 を描く。内容はテキスト層（80 桁×25 行の文字セル、01 章）に書く。属性 0xE1 = 通常（白）、0xE5 = 反転（カーソル）。
- テキスト層の 20 桁目・1 行目に「スイッチ %03d～%03d」（200q, 200q+199）。
- スイッチ 200q + i（i = 0〜199）のセル: 桁 (i mod 10)×4 + 21、行 (i ÷ 10) + 3。ON なら番号「%03d」、OFF なら「---」。カーソル位置（初期 i = 0）は反転属性。
- キー（キーバッファから 1 つずつ待つ。点滅なし・効果音なし）:
  - 取消: 終了。
  - 決定: カーソルのスイッチを反転（0↔1）。
  - →/←: 同じ行で桁を ±1（10 桁で回り込み）。↓/↑: 同じ桁で行を ±1（20 行で回り込み）。
  - 毎回、旧カーソルのセルを通常属性で、新カーソルのセルを反転属性で描き直す。
- 終了時: テキスト層をフィールド用マスクに戻す（文字を消し、左右 2 桁と最下行を黒く覆う属性にする。21 章）。

### 10.3 変数エディタ

- ウィンドウ (144, 0) 352×383。テキスト層 20 桁・1 行目に「変数 00～99  」。
- 変数 i（0〜99）: 桁 (i mod 5)×8 + 21・行 (i ÷ 5) + 3 に「%02d…」（番号と三点リーダ SJIS 0x8163）を通常属性で、桁 (i mod 5)×8 + 25 に値「%02d」をカーソルなら反転属性で。
- キー: 取消で終了。**ROLL UP** で値 +1（99 まで）、**ROLL DOWN** で値 −1（0 まで）。→/← で桁 ±1（5 桁で回り込み）、↓/↑ で行 ±1（20 行で回り込み）。
- 終了時はテキスト層をフィールド用マスクに戻す。
- 【参照実装では ROLL UP/DOWN を入力できないため、値の変更は事実上できない】。クリーン実装では PageUp/PageDown 等に割り当てるとよい。入力抽象への追加方法は 01 章 §4.3 の「任意の拡張：ROLL UP / ROLL DOWN」に従う。（v1.1 で追記）
- キー判定の順序：取消 → ROLL UP（値が 99 未満なら +1）→ ROLL DOWN（値が 0 より大きければ −1）→ → ← ↓ ↑。値が上限/下限で変えられないときはカーソルも動かない。どのキーでも（無関係なキーでも）旧カーソルのセルを通常属性・新カーソルのセルを反転属性で描き直す。キー待ちは 01 章 §4.3 の「打鍵があるまで待つ」（空にしない・STOP 検査なし）。スイッチビューアも同じ。（v1.1 で追記）

## 11. 店

店はイベントコマンド 0x3C（売買）・0x3D（購入のみ）・0x3E（売却のみ）から呼ばれる（22 章）。品物リストは最大 6 品。

共通部品:
- **店メッセージ(行 n, 番号 k)**: メッセージウィンドウ（22 章 §6.1）の第 n 行に「`\>` + WORD.DAT（0x670 + k × 0x1D）」を文章表示する（即時表示。`\@` は埋め込み文字列）。

| k | オフセット | 用途（サンプルの文言例） |
|---|---|---|
| 0 | 0x670 | 来店の挨拶「ご用は何ですか？」 |
| 1 | 0x68D | 購入時「何を買いますか？」 |
| 2 | 0x6AA | 売却時「何を売りますか？」 |
| 3 | 0x6C7 | 売値の提示「ひとつ\@になります。」（\@ = 売値） |
| 4 | 0x6E4 | 売却の確認「よろしいですか？」 |
| 5 | 0x701 | 購入成立「\@を買いました」（\@ = 品名） |
| 6 | 0x71E | 売却成立「\@を売りました」 |
| 7 | 0x73B | 所持金不足「お金が足りません。」（宿でも使う） |
| 8 | 0x758 | 持ちきれない「これ以上持てません。」 |
| 9 | 0x775 | 買い取り不可「この品物は買い取れません。」 |

- **店メッセージ消去**: (96, 256) から 320×40 を色 0 で塗る（第 0・1 行の左側だけ）。
- 所持金ウィンドウはすべて (0x198, 0x130)。

### 11.1 店（売買）0x3C

1. 取引成立フラグ := 0。
2. メッセージウィンドウを開き、所持金ウィンドウを表示。
3. 繰り返し:
   1. 店メッセージ消去、店メッセージ(0, 0)。
   2. 選択肢「買う」「売る」「やめる」（「やめる」が取消項目。22 章 §8 の 0x09 と同じ表示規則。x = 0x200 − 48 = 0x1D0）。
   3. ウィンドウ外の再描画（22 章 §6.1）。
   4. 「買う」→ §11.2、「売る」→ §11.3、「やめる」（または取消キー）→ 4 へ。
4. ウィンドウ外の再描画。メッセージウィンドウは開いたまま（イベント側で閉じられる）。

### 11.2 店（購入）（0x3D からも直接）

1. メッセージウィンドウを開き（内側消去）、所持金ウィンドウ、店メッセージ(0, 1)。
2. 品物ウィンドウ (0x50, 0x30) 大きさ 0xE0×(品数×24 + 24)。品 i の名前を (0x70, 0x40+24i)、価格を「%6d」（6 桁右詰め）で (0xF0, 0x40+24i)。装備可能かどうかの表示は **ない**。
3. カーソル（外字 SJIS 0xEB9F）を (0x60, 0x40 + 24×位置)（初期 0）に、§2.2 と同じ点滅・キー規則（↑↓回り込み、←→は効果音 1 のみ）で動かす。各フレームで STOP 検査。
4. 取消: 効果音 3、ウィンドウ外の再描画（品物ウィンドウを消す）、終了（売買店なら §11.1 に戻る）。
5. 決定: 効果音 2、カーソルを描く。店メッセージ消去。埋め込み文字列 := 品名。
   - 所持金 ≥ 価格なら所持品に追加を試み、
     - 失敗（99 個・満杯）: 店メッセージ(0, 8)。所持金は減らない。
     - 成功: 所持金を価格だけ減らし、所持金ウィンドウを描き直し、店メッセージ(0, 5)、取引成立フラグ := 1。
   - 所持金 < 価格: 店メッセージ(0, 7)。
   - 待ち記号つきキー待ち（22 章 §6.3）。店メッセージ消去、店メッセージ(0, 1)。3 に戻る（カーソル位置はそのまま）。
- 1 回の決定で 1 個買う。購入確認・個数指定はない。
- 0x3D（購入のみ）は手順の前に取引成立フラグを 0 にしない。
- 品数 0 の購入リストは未定義（実装は即終了を推奨）。

### 11.3 店（売却）（0x3E からも直接）

1. メッセージウィンドウを開き（内側消去）、所持金ウィンドウ。
2. 繰り返し:
   1. 店メッセージ(0, 2)。
   2. 所持品リスト（§2.3）を (0x90, 0x30) に開く。ページ・位置はフィールドメニューの所持品リストと**共有の記憶**を使う（店では初期化しない。メニューを開いたとき・戦闘開始時に 0 になる）。取消なら 3 へ。
   3. 店メッセージ消去。選んだアイテムの価格が 0 なら、店メッセージ(0, 9)、待ち記号つきキー待ち、店メッセージ消去して 2.1 へ。
   4. 売値 = 価格 ÷ 2（切り捨て）。0 なら 1。埋め込み文字列 := 売値の 10 進表記。
   5. 店メッセージ(0, 3)、店メッセージ(1, 4)。
   6. はい/いいえ選択（22 章 §8 の 0x08 の表示）。店メッセージ消去。
   7. 「はい」: 埋め込み文字列 := 品名。所持品から 1 個削除、所持金に売値を加える（上限 999999）、所持金ウィンドウを描き直し、店メッセージ(0, 6)、待ち記号つきキー待ち、店メッセージ消去、取引成立フラグ := 1。
   8. ウィンドウ外の再描画（リストを消す）。2.1 へ。
3. ウィンドウ外の再描画。
- 売れるのは所持品だけ（装備中の品は一覧に出ない）。「捨てられない」品も価格 ≠ 0 なら売れる。
- 0x3E は取引成立フラグを 0 にしない。

## 12. 宿屋（0x3F）

料金 P（符号付き 16 ビット）。

1. 取引成立フラグ := 0。返答 := はい。
2. P ≠ 0 なら:
   1. メッセージウィンドウを開き、所持金ウィンドウ (0x198, 0x130)。
   2. 第 0 行に「`\>`宿泊料金は<P を 10 進>< 単位 WORD.DAT 0x6F >です。」、第 1 行に「`\>`泊まりますか？」（いずれも内蔵文字列）。
   3. はい/いいえ選択。
3. P = 0 なら確認なしで「はい」として進む（ウィンドウも出さない）。
4. **はい**のとき:
   - 所持金 ≥ P（P は符号付きとして比較）なら:
     1. 取引成立フラグ := 1。所持金を P だけ減らす（P を符号なし 32 ビットに拡張して減算。P が負だと巨大値になり所持金は 0 になる）。
     2. BGM 再生要求「INN」（`DAT_BGM/INN.MML`）。
     3. 速度 2 のブラックアウト。
     4. ウィンドウ外の再描画、メッセージウィンドウを閉じる。
     5. パーティ全員に全回復（§1.9。旧版は HP +999 まで）。
     6. 2800 ミリ秒待つ。
     7. 毒フラグの更新。
     8. 速度 2 のブラックイン。
     9. 現在 BGM を再生要求（先頭から）。
   - 所持金 < P なら: ウィンドウ外の再描画、店メッセージ消去、店メッセージ(0, 7)（WORD.DAT 0x73B）、待ち記号つきキー待ち。ウィンドウは開いたまま。
5. **いいえ**のとき: ウィンドウ外の再描画、メッセージウィンドウを開く（内側を消去。開いたまま）。

宿の「お泊まりありがとう」などの追加メッセージはなく、文言が必要ならイベント側で 0x01 を使う。

## 14. 受け入れテスト観点

1. **経験値テーブル**: 任意の主人公（係数 A, B, C）で E(2)〜E(99) を §1.2 で計算し、PLAYER.DAT の初期状態（新規ゲーム開始時のステータス再計算後の「次の必要経験値」）と一致すること。
2. **レベル別ステータス**: 折れ点 K の前後で成長が半分になること。最大 HP 9999・その他 999 の上限。
3. **レベルアップ**: イベント 0x1E/0x20 で複数レベル上がる場合、各レベルの習得レベルの魔法がすべて覚えられること。HP は増えないこと。
4. **所持品**: 同一アイテム 99 個で追加失敗、捨てる・整理後に詰められていること。装備中のアイテムを 0x15 で減らすと装備が外れて消えること。
5. **所持判定**: 1996-06 版（MIND_A）では装備中の品が条件 9・ページ出現条件で「持っていない」扱いになること。
6. **全回復**: 旧版（MIND_A, BOUNTY）で最大 HP 1000 超の主人公が満タンにならないこと。
7. **メニュー画面**: JEWEL（`--no-title --warp 22,10,10`）でメニューを開き、コマンドウィンドウ (0x30,0x30)、パーティウィンドウ (0xC0,0x30)、テストプレイ欄 (0x30,0x120)、所持金ウィンドウが §3.2 の位置に出ること。並べ替え禁止（0x3B 引数 0）で「並び替え」が消え 4 項目になること。
8. **リスト**: 11 個以上の所持品で右矢印が出て、→ で 1 列ずつスクロールすること。カーソル位置がメニューを開き直すと 0 に戻ること。魔法リストは主人公ごとに位置を覚えること。
9. **装備**: 候補が「種類 = 部位+1」かつ装備可能ビットの品だけであること。空欄で決定すると外れて所持品に戻ること。予告の差分表示が正しいこと。
10. **アイテム使用**: 薬（単体）で対象選択、回復メッセージ。全体薬で 2 人目以降のメッセージの前に 28 VSYNC の間があること。何も起きないとき「しかし何も起こらなかった！」でアイテムが減らないこと。
11. **魔法使用**: MP 不足ではフラッシュの後に「〜が足りない！」が出て MP が減らないこと。フラッシュが 30 VSYNC で 10 回点滅すること。ばらつきの乱数の引き方（2 回）が戦闘と同じこと。
12. **ワープ・洞窟脱出**: 登録地点 0 件・禁止中・乗り物搭乗中は失敗表示になること。成功時はキー待ちなしで移動し、BGM が地点の BGM になること。
13. **セーブ/ロード**: SAVE1〜4.DAT のバイト列が 20 章の形式どおりであること。マップを編集して識別値が変わるとイベント状態が初期化されること。ロード後にフェードインすること。
14. **店**: agasa3・ygk の店で WORD.DAT 0x670〜0x775 の文言が使われ、`\@` に品名・売値が入ること。売値 = 価格÷2（最低 1）、価格 0 は買い取り不可。購入で所持品満杯なら所持金が減らないこと。条件 23（取引成立）が正しく立つこと。
15. **宿**: 料金表示、INN.MML の演奏、ブラックアウト中の全回復、2800 ms 後のブラックイン、元の BGM の再演奏。料金 0 では確認なし。
16. **デバッグ**: テストプレイ時のみ「デバッグ」が出ること。スイッチビューアのセル配置（10×20）、決定で反転。敵出現オフでエンカウントしないこと。
17. **毒**: 毒状態で歩くと 1 歩ごとに 1 回画面が白っぽく光り HP が 1 減ること。HP 1 で止まること。

## 15. 未確認事項・注意

- **魔法の失敗文のオフセット**: 本章の式（0x4A0 + (種別 + 9) × 0x1D）は 参照実装のフィールド・戦闘の両方で同じで、計算すると種別 0 → 0x5A5、種別 1 → 0x5C2 になる。サンプルの文言（0x5A5「しかし魔法は効かなかった！」、0x5C2「失敗してしまった！」など）とも整合する。24 章 §2.7・§12.9 も同じ値（0x5A5 / 0x5C2）で一致している。本章は 参照実装の式を正とした。原本での正しいオフセットは【未確認】。
- 失敗文に術者名や対象名を付けない点は 参照実装の実装どおり（【未確認】）。
- 変数エディタの ROLL UP/DOWN キーは 参照実装では入力できない（【参照実装では未実装】の入力経路）。
- セーブ時のイベント表の書き出しサイズ（参照実装は 250 バイト）。原本の形式は 20 章。
- 店の購入リストに装備可能表示は無い（参照実装の実装。原本も無いと思われるが【未確認】）。
- 0x3D/0x3E が取引成立フラグを初期化しない点、売却リストのカーソル記憶がメニューと共有である点は 参照実装の実装どおり。
- 宿の料金が負の場合、HP 回復量が負のアイテムなど、データの異常値に対する挙動は 参照実装の実装に基づく。
- §1.3 の式で「g × (K − 1)」だけ 16 ビットに切り詰める点は 参照実装の実装どおり（原本の 16 ビット演算の名残と思われる）。他の積は切り詰めない。
- 待ち時間（2800 ms など）はミリ秒指定。参照実装は VSYNC 56.42 Hz に換算（22 章 §6.2）。
- レベルアップ時の魔法習得のビルド差（§1.6）は 24 章の戦闘後のレベルアップにも同じく適用される。
