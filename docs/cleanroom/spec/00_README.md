# Dante98 / Dante98 II プレイヤー再実装 仕様書（クリーンルーム用）

## 0. この資料の位置づけ

この仕様書は、PC-9801 用ソフト「RPGツクール Dante98」（1992、以下 **D1**）と「RPGツクール Dante98 II」（1996、以下 **D2**）で作られたゲームを現代環境で動かすプレイヤー（ゲーム実行部 RPG.EXE と音源ドライバ MUSIC.COM に相当するもの）を、**クリーンルーム方式**で新規に実装するための資料である。

- **汚染側（本資料の作成側）**: リバースエンジニアリング情報をもとに作られた既存の再実装（参照実装）を読み、その振る舞い・データ形式・アルゴリズムを、コードを含まない自然言語に再構成した。
- **クリーン側（実装エージェント）**: この仕様書・公開資料・サンプルゲームのデータだけを使って実装する。

本資料は「何が起こるべきか」を記述し、「どうコードを書くか」は記述しない。データ構造の具体的な持ち方、モジュール分割、言語、ライブラリはクリーン側が自由に決めてよい。

## 1. クリーン側の運用規則

1. **既存実装のソースを見ない。** 参照実装のソースコード、wiki、コミット履歴を閲覧・検索・取得しない。他の非公開リバースエンジニアリング資料も使わない。
2. **原本のプログラムを解析しない。** ゲームに同梱されている RPG.EXE、MUSIC.COM、その他の実行ファイルを逆アセンブル・逆コンパイルしない。ただし次の 2 点は仕様の一部として許可する。
   - RPG.EXE の **版を判別するために、ファイル先頭の実行ファイルヘッダと決まった位置のバイト値を読むこと**（手順は 20_d2_data_formats.md）。
   - MUSIC.COM ファイル中の **版文字列の有無を調べること**（手順は 02_music_driver.md）。
3. **使ってよいもの**
   - この仕様書一式
   - サンプルゲームのデータファイル（画像・マップ・データベース・MML・SOUND.DAT など）。これを読み解いて仕様の記述を確かめるのは自由。
   - 一般に公開されている資料（PC-9801 のハードウェア資料、YM2203/YM2608 のデータシート、MUSIC.COM の MML リファレンス、ツクールのマニュアル）
   - 第三者の汎用ライブラリ。特に次の 2 つは 参照実装とは無関係の独立した成果物なので、利用してよい。
     - **ymfm**（BSD-3-Clause）: YM2203（OPN）の音源チップエミュレータ
     - **東雲フォント**（パブリックドメイン）: 16×16 の JIS X 0208 全角と 8×16 の半角のビットマップフォント。NEC の漢字 ROM の代わりに使う。
4. 仕様の記述が曖昧なとき、または矛盾しているときは、推測で埋めずに「仕様への質問」として記録し、汚染側に問い合わせる。応急の実装を入れる場合は、仮の実装であることをコードとテストに明記する。
5. 仕様書中の「**【未確認】**」は、既存実装でも確証のない挙動を指す。「**【参照実装では未実装】**」は、既存実装にも入っていない挙動を指す。どちらも互換性の判定基準から外し、後回しにしてよい。

## 2. 対象範囲

| 対象 | 内容 |
|---|---|
| 含む | D1 / D2 ゲームの実行（タイトル、フィールド、イベント、メニュー、戦闘、セーブ/ロード、エンディング）、MUSIC.COM 互換の BGM と効果音、PC-98 の画面の再現（640×400、16 色）、ゲームの判別とゲーム選択画面、テスト用のヘッドレス実行器 |
| 含まない | エディタ（ツクール本体）、ゲームデータの圧縮/展開ツール、PC-98 の CPU 命令レベルのエミュレーション、MS-DOS 環境の再現 |

方針として、原本を「実行」するのではなく、原本の **挙動を高水準で再実装** する。画面は 640×400 ドット・16 色のフレームバッファとして作り、毎 VSYNC（約 56.4Hz）に 1 枚ずつ表示側へ渡す。音は MUSIC.COM と同じ規則で YM2203 にレジスタを書き込み、チップエミュレータで PCM を作る。

## 4. 推奨アーキテクチャ（参考）

各層の責任範囲だけを示す。具体的な分け方はクリーン側が決めてよい。

1. **プラットフォーム層**: ウィンドウと画面表示、キー入力、音声出力デバイス、ファイルシステム。OS とライブラリに依存する部分はここに集める。ここを差し替えれば別の環境へ移植できるようにする。ヘッドレス版（画面なし、スクリプト入力、PNG/WAV 出力）も、この層の実装の 1 つとして作る。
2. **共通層**: 640×400 の 16 色フレームバッファ、テキスト層、パレット、合成処理（→ 01）、フォントと Shift-JIS の処理、乱数、大文字小文字を区別しないファイル探索、MUSIC.COM 互換ドライバと YM2203 エミュレータ（→ 02）。
3. **エンジン層（D1 / D2 で別実装）**: ゲームの状態、フィールド、イベント、メニュー、戦闘。
4. **アプリケーション層**: ゲームの判別、ゲーム選択画面、セッションの開始と終了。

スレッドの構成例: ゲームロジックは専用スレッドで動かし、1 VSYNC ごとに「フレームを渡してから次の VSYNC まで待つ」呼び出しを行う。原本のコードは「VSYNC を待つ」ループで時間を進めるので、この形にすると原本のタイミングをそのまま写せる。音声はオーディオスレッドでチップを駆動する。ゲームスレッドからの音の要求（BGM 再生、停止、フェード、効果音）はキューに積み、オーディオスレッド側で反映する。

## 5. 表記規則

- 数値の `0x` 付きは 16 進。バイトオフセットはすべて 0 起点。
- 多バイト整数はすべて **リトルエンディアン**。型は次の記号で書く。

  | 記号 | 意味 |
  |---|---|
  | `u8` / `i8` | 符号なし / 符号付き 8 ビット |
  | `u16LE` / `i16LE` | 符号なし / 符号付き 16 ビット |
  | `u32LE` | 符号なし 32 ビット |
  | 文字列(SJIS, n) | n バイト固定長の Shift-JIS 文字列。末尾は NUL 埋めまたは空白埋め（各表に明記） |

- 画面座標は左上を原点とするドット単位（x: 0–639、y: 0–399）。テキスト層の座標は桁（0–79）と行（0–24）で表す。
- 「1 VSYNC」は表示の垂直同期 1 回分（約 1/56.4 秒）。待ち時間は原則として VSYNC の回数で書く。
- 「乱数を 1 回引く」は、共通の線形合同法乱数（→ 01）から値を 1 つ取り出すことを指す。乱数の結果は引く順序と回数で変わるので、仕様に書かれた順番どおりに引くこと。
- 色番号は 16 色パレットのインデックス（0–15）。

## 6. 用語集

| 用語 | 意味 |
|---|---|
| D1 / D2 | RPGツクール Dante98 / Dante98 II、およびそれで作られたゲーム |
| RPG.EXE | 各ゲームに同梱されている実行部。このプロジェクトはこれを置き換える |
| MUSIC.COM | 同梱の FM 音源ドライバ。MML テキストを読み込んで演奏する。このプロジェクトでは互換ドライバを作る |
| MML | 曲データのテキスト形式（Music Macro Language） |
| SOUND.DAT | 効果音の定義が書かれたテキストファイル |
| OPN / YM2203 | PC-9801-26K に載っている音源チップ。FM 3 チャンネルと SSG（矩形波）3 チャンネルを持つ |
| VSYNC | 表示の垂直同期。ゲームの時間の基本単位 |
| プレーン形式 | PC-98 のグラフィックの格納形式。1 画素 4 ビットを、色ビットごとの面（B, R, G, I）に分けて格納する |
| テキスト層 | PC-98 のテキスト VRAM に相当する層。80×25 桁の文字セルで、グラフィック面の上に重なる |
| 外字 | ゲームごとに定義する 16×16 の文字グリフ（D2 の GAIJI.DAT） |
| チップ | マップを構成するタイル。D2 では 1 チップが 32×32 ドット、1 マップあたり 160 種類 |
| パターン | D2 の 32×32 のマスク付き画像の単位。ECD 系ファイルに並んで入っている |
| イベント | マップ上に置かれた NPC や仕掛け。ページと、ページごとのスクリプトを持つ |
| ページ | イベントの状態の候補。出現条件、見た目、動き、起動条件、スクリプトを持つ |
| スイッチ / 変数 | イベントが使うフラグと数値。D1 はスイッチのみ（200 個）、D2 はスイッチ 1000 個と変数 |
| ビルド（版） | D2 の RPG.EXE には複数の版（1996-06、1996-08、1997-03、1997-10）があり、いくつかの規則が違う |
| テストプレイモード | D2 のエディタから起動したときの動作。タイトル画像を飛ばし、デバッグメニューを使える |

### 6.1 章によって呼び方が違う用語

章ごとに担当者が別だったため、同じものを違う名前で呼んでいる箇所がある。次の表の語はすべて同じものを指す。

| 対象 | 呼び方 | 補足 |
|---|---|---|
| D2 の層（階層） | 上層 / 地上 = 0x00、下層 / 地下 = 0x20、連結部 = 0x60 | 20・21 章は「上層 / 下層」、22 章は「地上 / 地下」と呼ぶ。値は同じ |
| 空の乗り物 | 飛空艇 | 一部に残る「飛行船」も同じもの |
| 脱出地点 | 洞窟脱出地点 / 脱出地点 | 「洞窟脱出」の魔法とアイテム、イベントコマンドが使う戻り先 |
| マップの版番号 | マップ版数 / マップ識別値 | マップファイル中の値。セーブデータとマップが合っているかの照合に使う（20・23 章） |
| D2 RPG.EXE の版 | 1996-06 版 = 96/06、1996-08 版 = 96/08、1997-03 版 = 97/03、1997-10 版 = 97/10 = 標準版 | 「旧版」は 1996-06 版と 1996-08 版を指す。判別できない RPG.EXE は標準版として扱う |
| 効果音番号 | エンジン内部の番号 n と、SOUND.DAT のレコード番号 | D2 は SOUND.DAT のレコード番号 n + 10 を要求する（02 章 §5.3） |

## 7. サンプルゲーム

ユーザーから提供されたサンプルゲームを使って検証する。サンプル一式は `samples/` の下に、`samples/games/<アーカイブ名>/…`（LHA の自己解凍アーカイブを展開したもの）と `samples/d1/<名前>/…` の形で置く前提で、各章もこのパスで参照している。各ディレクトリの中で RPG.EXE がある場所がゲームのルートになる。D1 が 20 本、D2 が 23 本ある。ファイル名の大文字小文字はゲームごとにまちまちなので、ファイル名は大文字小文字を区別せずに照合すること。

| エンジン | ゲーム（アーカイブ名） |
|---|---|
| D1 | agasa, azusa, clock, come, corpse, daiti, dm, em, illusion, lost (LostSheep), nuigl, social, cook, earth, haru（春の嵐）, kaze（風薫るとき）, maho, night, olsay, wicca |
| D2 | 0204_ace, 05yakata, agasa3, bounty, brtsky, dino, disaster, fant1_8, fantasia, jewel, keep, knuckle, kokoro, mind_a, ring, rogues, soul, syuujin, tokiake, ue, waste_w, ygk, zyuken |

注意: azusa、brtsky、zyuken は、アーカイブの中で `WINDOWS/ﾃﾞｽｸﾄｯﾌﾟ/<ゲーム名>/` という、半角カナを含む深い階層に入っている。ゲームを探す処理（→ 01）では、このような階層とフォルダ名も扱えるようにすること（既存実装のゲーム選択画面には、この 3 本が表示されていなかった）。brtsky と zyuken は D2、azusa は D1 である。

D2 の各サンプルが RPG.EXE のどの版にあたるかは、20_d2_data_formats.md の表を参照。

## 8. 互換性の判定基準

優先順位の高い順に並べる。

1. **データを正しく読めること**: 全サンプルゲームについて、全データファイルを例外なく読み込める。
2. **ゲームが進行すること**: タイトルからゲーム開始、フィールドの移動、イベント、戦闘、セーブ/ロードが破綻しない。
3. **数値が一致すること**: ダメージ、経験値、ステータス、所持金などの計算結果が仕様と一致する。乱数のシードを固定した場合は、乱数を引く順序まで一致させる。
4. **画面が一致すること**: ウィンドウの位置、文字の位置、色、演出（フェード、フラッシュ、揺れ）が仕様と一致する。グリフの形はフォントの違いによる差を許す。
5. **タイミングが一致すること**: 待ちの VSYNC 数、移動速度、音のテンポ。
6. **音が一致すること**: MML の解釈と効果音が一致する。
